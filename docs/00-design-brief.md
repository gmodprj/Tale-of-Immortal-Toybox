# 귀곡팔황(Tale of Immortal) 통합 치트·샌드박스 모드 설계 및 창작마당 조사

> 작성일: 2026-10-11  
> 범위: 플레이어, NPC, 아이템, 경지, 공법·무공, 관계, 문파, 세계, 전투, 이벤트, 저장 및 Steam 창작마당 참고 모드  
> 문서 성격: 개발 기획서 + 조사 목록. **기능 후보는 구현이 확인된 게임 API가 아니며**, 링크가 존재한다는 사실만으로 현재 버전 호환성이 보장되지 않는다.

## 1. 프로젝트 목표

귀곡팔황의 주요 데이터를 조회·편집하고, 게임 규칙을 선택적으로 바꾸는 통합형 모드 `GGBH Cheat Sandbox`를 제작한다. 단순 수치 치트에서 시작해 공법 에디터, NPC 관계 편집, 경지 확장 연구, 세계 샌드박스까지 단계적으로 확장한다.

### 1.1 설계 원칙

1. **읽기 → 검증 → 백업 → 변경 → 재조회** 순서를 지킨다.
2. 게임 버전별 클래스/필드/메서드는 `GameVersionAdapter`로 격리한다.
3. 런타임 패치, 게임 공식 모드 데이터, 세이브 편집은 서로 다른 경로로 취급한다.
4. 저장 파일을 손상시킬 수 있는 경지·관계·NPC 생성·이벤트 변경은 별도 테스트 세이브에서만 시험한다.
5. 다른 창작마당 모드의 기능을 참고하되, 소스 코드 재사용은 라이선스를 확인한다.

## 2. 기능 분류와 우선순위

| 분야 | 기본 치트(MVP) | 확장 편집기 | 고위험 샌드박스 |
|---|---|---|---|
| 플레이어 | 재화·체력·수명·기본 능력치 | 자질·기운·특성·스탯 배율 | 사망·노화 규칙 변경 |
| NPC | 이름/경지 검색, 호감도 | 성격·특성·인벤토리·공법·경지 | 생성·삭제·이동·AI 조정 |
| 아이템 | 검색·추가·수량 변경 | 품질·옵션·복사·분해 | 신규 아이템 정의 |
| 경지 | 현재 경지·단계 조회, 돌파 보조 | 강제 돌파·재료 무시·경지별 수련 배율 | 신규 경지·돌파 단계 추가 |
| 공법/무공 | 숙련도·경험치·품질 조절 | 옵션 편집·경지 승급·융합·계승 | 신규 기술·효과·발동 규칙 |

| 문파 | 공헌·재화 | 직급·구성원·자원 | 세력 관계·문파 재편 |
| 세계 | 시간·이동 편의 | 자원·탐색·지역 해금 | 이벤트 생성·세계 상태 변경 |
| 전투 | 무적·피해 배율·쿨타임 | 적 능력치·드랍·전투속도 | 적 생성·AI 변경 |

우선순위: **P0** 안전한 읽기/백업 → **P1** 플레이어·재화·아이템 → **P2** NPC·관계 → **P3** 공법·경지 → **P4** 전투·세계 → **P5** 신규 콘텐츠.

## 3. 플레이어 모듈

### 3.1 조회 필드 후보

- 식별: 고유 ID, 이름, 성별, 나이, 수명, 위치, 문파.
- 전투: 체력, 영력, 공격, 방어, 이동속도, 치명타, 회피 등 실제 게임에 존재하는 필드.
- 성장: 경지, 경지 단계, 수련 경험치, 자질, 선천·후천 기운, 공법 목록.
- 경제: 영석, 문파 공헌, 아이템 및 재료 수량.

### 3.2 편집 기능

- 현재값/최댓값 구분 편집, 고정값·배율 적용, 수명 증가, 자원 회복.
- `MAX` 버튼은 무조건 정수 최대값을 입력하는 것이 아니라 게임이 허용하는 상한을 확인한 후 적용.
- 모든 편집은 저장 전후 값을 로그로 남긴다.

## 4. NPC 모듈

검색 필터: 이름, 고유 ID, 경지, 문파, 지역, 관계 유형. 상세 편집은 정체성/능력치/특성/경지/공법/소지품/관계 탭으로 나눈다.

**주의:** NPC의 경지를 직접 수정하면 체력 상한, 수명, 공법 사용 가능 여부, AI 전투력 등이 일치하지 않을 수 있다. 관련 데이터 재계산 함수가 확인되기 전에는 경지 직접 쓰기를 잠근다. NPC 삭제·생성은 이벤트 참조와 관계 그래프에 영향을 줄 수 있어 후순위로 둔다.

## 5. 경지·돌파 시스템

대표 경지 흐름(게임 버전 및 번역에 따라 표기 차이 가능):

`연기(炼气) → 축기(筑基) → 결정(结晶) → 금단(结丹) → 원영(元婴) → 화신(化神) → 오도(悟道) → 우화(羽化) → 등선(登仙)`

경지 편집기는 다음을 별개로 관리한다.

- **캐릭터 경지:** 현재 경지, 세부 단계, 수련치, 돌파 조건.
- **공법 경지:** 공법이 요구하는 경지와 품질, 강화 가능한 상한.
- **돌파 절차:** 재료 검사, 조건 검사, 성공률, 성공 후 능력치 보정.
- **신규 경지 추가:** UI, 수련 테이블, 능력치 스케일링, 드랍/적, NPC AI, 세이브 직렬화까지 검토해야 하는 별도 프로젝트.

신규 경지 모드는 단순 수치 확장과 구분한다. 현재 대화에서 확보된 자료만으로 **실제 신규 경지를 추가하는 특정 창작마당 모드를 검증했다고 볼 수 없다.**

## 6. 공법·무공·신통 상세 설계

### 6.1 분류

| 구분 | 중국어 검색어 | 편집 항목 후보 |
|---|---|---|
| 무기술/일반 공격 | 武技, 灵技 | 피해, 발사체, 사거리, 속도, 쿨타임 |
| 절기 | 绝技 | 소모 자원, 피해, 조건, 효과 |
| 신법 | 身法 | 이동·회피·지속시간·쿨타임 |
| 신통 | 神通 | 발동 조건, 소모, 범위, 효과 |
| 심법 | 心法 | 스탯 보너스, 성장, 옵션 |
| 공법 일반 | 功法 | 경지, 품질, 경험치, 숙련도, 옵션 |

### 6.2 공법 데이터 개념 모델

```text
Technique
 ├─ identity: instanceId / templateId / name
 ├─ category: 武技 / 灵技 / 绝技 / 身法 / 神通 / 心法
 ├─ progression: realm / quality / level / xp / mastery
 ├─ entries[]: optionId / value / quality / lockState
 ├─ effects[]: effectId / parameters / conditions
 └─ ownership: playerId / npcId / inventorySlot
```

위 구조는 **설계용 추상 모델**이며 실제 게임 내부 필드명은 아니다.

### 6.3 공법 에디터 기능

1. 공법 검색·필터·상세 조회.
2. 공법 경험치/숙련도 증가 및 성장 배율 설정.
3. 경지·품질 업그레이드와 한계값 검사.
4. 옵션 추가·삭제·교체·잠금·재추첨 시 하락 방지.
5. 공법 복제·융합·계승·분해(원본과 결과물 미리보기 필수).
6. 피해·범위·발사체·지속시간·쿨타임 등 효과 변경(실제 매핑 검증 후).
7. 공법 이름 변경 및 NPC에게 지급.

### 6.4 공법 융합 처리

`원본 A + 재료 B → 옵션 선택 → 중복/충돌 검사 → 결과 미리보기 → 백업 → 적용 → 재조회`

옵션 ID가 같아도 중첩 가능 여부, 수치 상한, 요구 경지 등이 다를 수 있으므로 단순 배열 합치기는 금지한다.

## 7. 아이템 모듈

아이템 검색 조건: ID, 이름, 종류, 경지, 품질. 생성 시 수량·품질·부가 옵션을 입력하고 실제 인벤토리 수용 여부를 검사한다. 스택형 아이템과 고유 인스턴스형 공법/장비를 분리한다. 아이템 생성 후 게임의 인벤토리 갱신 경로를 통해 UI 반영 여부를 검증한다.

## 8. 관계·문파 모듈

관계 편집: 호감도, 원한, 친구/연인/배우자/사제 등 관계 유형. 관계는 양방향 참조 및 NPC AI 조건과 연결될 수 있으므로 일괄 호감도 MAX 같은 기능에도 변경 대상 수, 예상 부작용, 되돌리기 계획을 표시한다.

문파 편집: 가입/탈퇴, 직급, 공헌, 재화, 구성원, 외교 관계. 문파장 교체·문파 삭제 등은 이벤트 및 NPC 상태와 연결되므로 후순위.

## 9. 세계·이벤트·전투 모듈

- 세계: 시간 진행/정지, 지역 이동, 지도 해금, 채집량·드랍 배율.
- 이벤트: 이벤트 ID 조회, 선행조건 검사, 재실행 가능성 확인. 강제 발생/완료는 별도 테스트.
- 전투: 무적, 자원 소모 0, 쿨타임 배율, 공격/피해 배율, 적 체력/AI 조정.
- 전투 훅은 **플레이어에게만 적용**할지, 동료·NPC·몬스터에게도 적용할지 명시하여 범위 오염을 방지한다.

## 11. 기술 구조 및 역공학

이전 대화에서는 Unity, IL2CPP, MelonLoader, Harmony, 게임의 `ModCode/ModExcel/ModAssets` 계열을 참고 기술로 제시했다. **실제 설치 버전에서 로더/백엔드/공식 모드 API의 적합성을 먼저 검증**해야 한다. Unity 프로젝트라고 해서 모든 버전이 동일한 패치 구조를 제공하지는 않는다.

```text
GGBH-CheatSandbox/
├── README.md
├── docs/
│   ├── compatibility.md
│   ├── reverse-engineering.md
│   ├── player.md
│   ├── npc.md
│   ├── technique.md
│   ├── realm.md
│   └── workshop-research.md
├── src/
│   ├── Core/             # 로깅, 설정, 버전 확인
│   ├── Adapters/         # 게임 버전별 접근
│   ├── Resolvers/        # 실제 게임 객체 조회
│   ├── Services/         # 검증된 변경 작업
│   ├── Features/         # Player/NPC/Item/Realm/Technique 등
│   ├── UI/               # 검색·편집·미리보기

└── tests/
    ├── compatibility/
    └── save-regression/
```

### 11.2 개발 검증 순서

1. 게임 버전, 모드 로더, 현재 설치 모드 목록 기록.
2. 빈 테스트 세이브 및 백업 생성.
3. 플레이어/아이템/NPC 조회만 하는 읽기 전용 프로토타입 제작.
4. 영석처럼 단순한 한 항목을 변경하고 게임 재시작 후 지속성 확인.
5. 공법 인스턴스·템플릿·옵션 테이블 관계 조사.
6. 경지 변경 전후 파생 스탯 및 NPC AI 확인.
7. 관계·문파·세계 변경을 별도 세이브에서 검증.

## 12. UI 기획

```text
[F8] GGBH SANDBOX
 ├─ 대시보드: 게임/모드 버전, 세이브 상태, 최근 변경
 ├─ 플레이어: 기본 정보 / 능력치 / 자원 / 수명
 ├─ NPC: 검색 / 상세 / 경지 / 특성 / 관계
 ├─ 아이템: 검색 / 생성 / 수량 / 품질
 ├─ 경지: 단계 / 돌파 / 재료 / 수련 배율
 ├─ 공법: 검색 / 성장 / 옵션 / 강화 / 융합
 ├─ 문파: 공헌 / 직급 / 구성원
 ├─ 세계: 시간 / 지역 / 자원 / 이벤트
 ├─ 전투: 무적 / 피해 / 쿨타임 / 적
 └─ 안전: 백업 / 변경 이력 / 호환성 진단
```

`F8`은 **제안 단축키**이며 게임에서 충돌 여부 확인 후 설정 가능하도록 한다.
