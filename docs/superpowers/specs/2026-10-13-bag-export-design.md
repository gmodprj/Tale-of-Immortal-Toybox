# 가방 내보내기·가져오기 — 설계 스펙 (묶음 C)

> 작성일: 2026-10-13 · 대상 게임 버전: v1.2.113.259 · 모드 ID: `sWP6UL`
> 선행 문서: `docs/06-handoff.md`(8.4절), `docs/05-editor-v0.1.md`(25~27절), `docs/superpowers/specs/2026-10-13-ui-rework-design.md`

## 1. 목적

현재 가방을 이름을 붙여 파일로 내보내고, 내보낸 것을 골라 지금 가방으로 가져온다. 사용자가 고른 용도는 둘이다.

- 아이템 묶음 보관: 자주 쓰는 구성을 저장해 두고 어느 세이브에서든 꺼낸다.
- 다른 세이브·새 인물로 옮기기: 장비와 비급의 내용까지 같게 넘긴다.

끝난 기준: 6절의 검증이 게임에서 통과한다.

## 2. 범위

사용자와 정한 것(2026-10-13):

| 항목 | 결정 |
|---|---|
| 담는 것 | 가방의 아이템, 장착 중인 장비·단약 칸의 것, 영석과 화폐 9종 |
| 가져오기 | 항상 지금 가방에 더한다. 가방을 비우고 채우는 "교체"는 없다 |
| 세이브에 묶인 아이템 | 문자열을 가진 아이템(종문 추천서 등)은 내보내기에서 뺀다. 뺀 수를 알린다 |
| 칸이 모자랄 때 | 조용히 늘리지 않는다. `가방을 늘리고 모두` / `들어가는 만큼만`을 고르게 한다 |
| 위치 | 새 탭 "보관함"(화폐 다음). 묶음 D도 이 탭에 얹는다 |
| 파일 | JSON, 내보내기 하나에 파일 하나, 이름은 화면에서 정한다 |

요청 원문(4-1~4-4): JSON 외부 파일, 화면에서 이름 지정, 목록에서 골라 전부 가져오기, 세부 목록에서 아이템을 하나씩 가져오기.

### 범위 밖

- 가져온 장비의 자동 장착.
- 내보낸 파일을 화면에서 고치기(이름 바꾸기, 아이템 빼기). 파일을 직접 고칠 수는 있다.
- NPC의 가방.
- 캐릭터 내보내기(묶음 D).

## 3. 실측으로 확인한 사실 (2026-10-13)

개발 전용 명령으로 사용자의 세이브에서 실험했다(회차 `bagx-r1`, `bagx-r2`). 끝난 뒤 세이브를 되돌려 일치를 확인했다. 실험 명령은 `feat/bag-export-research` 브랜치의 `Dev/DevCommandsBag.cs`에 있다(`develop`에 병합하지 않음).

| 항목 | 실측 |
|---|---|
| 가방 | `unit.data.unitData.propData`(`DataProps`)의 `allProps`. 시험 세이브는 91개 |
| 아이템 하나 | `DataProps.PropsData`: `soleID`, `propsID`, `propsCount`, `propsType`, `values`(정수 배열), `GetValuesStrArray()`, `GetValuesLocalTextArray()` |
| `values`의 머리 | 앞의 세 칸은 종류(1 일반, 2 비급), 번호, 수량이다. 일반 아이템은 이 세 칸이 전부였다(`[1,3011011,1]`). 비급은 그 뒤에 값이 더 붙는다(`[2,0,1,2,23116,3,5,4,-1,45,1]`, `propsID`는 0) |
| 종류 | `propsType`은 `Props` 87개, `Martial` 4개 |
| 문자열 | 91개 중 2개(종문 추천서 6071014)만 가졌다. 내용은 그 세이브의 NPC 번호와 이름, 종문 이름이다 |
| 장착 | 장착한 것도 `allProps` 안에 있고 `unitData.IsEquipProps(soleID)`가 `true`다. 장비 칸은 `unitData.equips`(2개), 단약 칸은 `unitData.props`(5개) |
| 다시 만들기 | `PropsData.New(propsID, propsCount, propsType, values의 넷째 칸부터)`로 만들어 `DataProps.AddProps(PropsData)`로 넣으면 원본과 내용(번호·수량·종류·값·문자열)이 같다. 장비, 비급 두 가지(값 11칸, 17칸), 문자열 아이템에서 확인. `values` 전체를 넘기면 머리 세 칸이 두 번 들어간다 |
| 고유 번호 | `New`가 새 `soleID`를 준다. `Clone()`은 원본과 같은 `soleID`를 가진 것을 만든다(쓰지 않는다) |
| 겹침 | 같은 번호의 겹쳐지는 아이템은 이미 있는 묶음에 합쳐진다(`allProps`의 수와 쓰는 칸이 그대로). 가방이 가득 차 있어도 들어간다 |
| 가득 찬 가방 | 겹쳐지지 않는 것을 `AddProps`로 넣으면 예외 없이 안 들어간다(`allProps`의 수 그대로, 반환 목록의 길이는 1). 넣은 뒤 수를 다시 읽어야 안다 |
| 재화 | 영석과 화폐는 `RewardPropMoney`, `RewardPropItem`으로 오르고 가방 칸을 쓰지 않는다(05 문서 27절) |

### 확인하지 못한 것

- 강화하거나 옵션이 붙은 장비(시험 세이브의 장비는 값이 머리 세 칸뿐이었다). 값 배열에 들어 있다면 그대로 옮겨진다.
- 가져온 비급을 게임에서 실제로 배우는 동작.
- 법보·영수 같은 특수 아이템, 내구도(`dynDurable`).
- `RewardPropItem`을 가방이 가득 찬 상태에서 겹쳐지지 않는 아이템에 부르자 개발 명령이 응답하지 않았다(게임이 무엇을 띄웠는지 확인하지 못했다). 가져오기는 이 경로를 재화에만 쓴다.

## 4. 결정 사항

- 아이템은 `PropsData.New` + `AddProps(PropsData)`로 넣는다. 넣기 전후의 `GetPropsNum`(일반) 또는 `allProps`의 수(비급)를 비교해 들어갔는지 확인한다.
- 문자열 배열이 비어 있지 않은 아이템은 내보내지 않는다.
- 필요한 칸은 "겹쳐지지 않는 아이템의 수 + 가방에 아직 없는 겹쳐지는 아이템의 종류 수"로 센다. 겹쳐지는지는 게임의 아이템 표(`ConfItemPropsItem.isOverlay`)로 본다.
- 가방을 늘릴 때는 `BagService.Change`를 쓴다(10칸 단위로 올림, 상한 +500). 상한 때문에 다 못 늘리면 들어가는 만큼만 넣는다.
- JSON은 직접 읽고 쓴다. 참조를 추가하지 않는다.
- 파일의 삭제는 두 번 눌러 확인한다.

## 5. 설계

### 5.1 파일

위치: `<세이브 뿌리>\TlToybox\exports\bag\<파일 이름>.json`. 파일 이름은 화면에서 적은 이름에서 파일에 쓸 수 없는 글자를 `_`로 바꾼 것이다. 같은 이름이 있으면 `이름 (2)`, `이름 (3)`으로 저장한다. UTF-8.

    {
      "format": 1,
      "kind": "bag",
      "name": "돌파 재료 세트",
      "exportedAt": "2026-10-13 14:30:00",
      "character": "신환",
      "skipped": 2,
      "items": [
        { "id": 3011011, "name": "석침계", "count": 1, "type": "Props", "values": [], "equipped": true },
        { "id": 0, "name": "(비급)", "count": 1, "type": "Martial", "values": [2, 23116, 3, 5, 4, -1, 45, 1], "equipped": false }
      ],
      "currencies": [
        { "id": 10001, "name": "영석", "count": 177643 }
      ]
    }

- `values`는 머리 세 칸을 뺀 나머지다. `name`은 사람이 읽기 위한 것이고 가져올 때는 쓰지 않는다. 비급의 이름은 공법 서비스가 주는 이름을 적는다.
- `skipped`는 문자열 때문에 뺀 아이템의 수다.
- 읽을 때 `format`이 1이 아니거나 `kind`가 `bag`이 아니거나 문법이 틀리면 "읽을 수 없음"으로 다룬다. 모르는 필드는 무시한다. 게임에 없는 번호의 아이템은 가져올 때 건너뛰고 알린다.

### 5.2 코드 구조

| 파일 (`src/ModCode/ModMain/`) | 맡는 일 |
|---|---|
| `Services/Json.cs` (새 파일) | 작은 JSON 읽기·쓰기(객체, 배열, 문자열, 정수, 불). 화면과 게임을 모른다 |
| `Services/BagExportService.cs` (새 파일) | 내보내기, 목록, 읽기, 가져오기(하나·전부), 필요한 칸 계산, 삭제. 결과를 문장으로 돌려준다 |
| `UI/Tabs/VaultTab.cs` (새 파일) | 보관함 탭: 목록 화면과 세부 화면(`Push`) |
| `UI/EditorWindow.cs` | 탭 목록에 보관함을 화폐 다음에 넣는다 |

    BagExportService.Export(name)                    // 결과 문장. 파일을 쓴다
    BagExportService.List()                          // 내보낸 것들(이름, 날짜, 인물, 아이템 수, 읽을 수 있는지)
    BagExportService.Load(file)                      // 한 파일의 내용
    BagExportService.NeededSlots(pack)               // 지금 가방에 전부 넣을 때 더 필요한 칸
    BagExportService.ImportItem(pack, index)         // 하나. 결과 문장
    BagExportService.ImportCurrency(pack, index)
    BagExportService.ImportAll(pack, expandBag)      // 전부. 결과 문장(넣은 수, 못 넣은 것)
    BagExportService.Delete(file)

쓰기 전에 `SaveBackup.EnsureOnce()`, 쓰기 뒤에 `ChangeLog.Add`(기존 규칙). `ImportAll`은 이력에 한 줄(무엇을 몇 개 넣었는지)을 남긴다.

### 5.3 화면

보관함 탭(목록):

    이름 [                    ] [현재 가방 내보내기]     가방 89/154 · 세이브에 묶인 아이템(종문 추천서 등)은 담지 않습니다
    ------------------------------------------------------------------------------------------
    이름              날짜                 인물    아이템  화폐
    돌파 재료 세트     2026-10-13 14:30     신환     89     10    [세부] [모두 가져오기] [삭제]
    (읽을 수 없음) x.json                                                              [삭제]

- 목록은 `ListView`, 최신이 위. 이름 검색은 `SearchBox`.
- `모두 가져오기`: 필요한 칸이 빈 칸보다 많으면 결과 영역에 "필요 N칸, 빈 칸 M칸"을 보이고 그 줄의 버튼이 `가방을 늘리고 모두`와 `들어가는 만큼만`으로 바뀐다(`Confirm`과 같은 방식의 대기, 다른 동작을 하면 풀린다). 모자라지 않으면 바로 가져온다.
- `삭제`는 `Confirm`.

세부 화면(`Push`):

    돌파 재료 세트 — 신환, 2026-10-13 14:30                                      [돌아가기]
    [검색                ×]   아이템 89 · 화폐 10 · 뺀 것 2
    번호      이름            수량   종류   장착              [가져오기]
    ...
    10001     영석           177643  화폐                     [가져오기]

- 아이템과 화폐를 한 `ListView`에 보인다(화폐는 뒤쪽, 종류 열에 "화폐"). 줄마다 `가져오기`.
- 화폐의 `가져오기`는 그 수량만큼 더한다.

### 5.4 가져오기의 순서 (`ImportAll`)

1. 세이브 백업.
2. `expandBag`이면 모자란 칸만큼 `BagService.Change`(10칸 단위로 올림).
3. 겹쳐지는 아이템부터 넣는다(칸을 쓰지 않거나 한 칸만 쓴다). 그다음 겹쳐지지 않는 것을 파일의 순서대로 넣는다.
4. 하나 넣을 때마다 들어갔는지 확인한다. 안 들어간 것은 이름과 수를 모은다.
5. 화폐를 넣는다.
6. 결과: "아이템 N개 가져옴, 화폐 M종, 못 넣은 것 K개: 이름, 이름…". 못 넣은 이름이 많으면 앞의 다섯 개와 "외 n개".

## 6. 검증

`session.ps1` 회차 안에서, `tools/research/ui-check.ps1`에 부분을 더해 한다.

| # | 시험 | 기대 |
|---|---|---|
| 1 | 이름을 적고 내보내기 | 파일이 생기고 목록 맨 위에 나온다. 아이템 수 = 가방의 수 - 문자열 아이템의 수. JSON으로 읽힌다 |
| 2 | 같은 이름으로 한 번 더 | `이름 (2)` 파일이 생긴다 |
| 3 | 이름에 파일에 쓸 수 없는 글자를 넣어 내보내기 | 그 글자가 `_`로 바뀐 파일이 생긴다 |
| 4 | 세부 화면 | 아이템과 화폐가 보이고 검색된다 |
| 5 | 세부에서 장비 하나 가져오기 | 가방에 하나 늘고 값이 원본과 같다 |
| 6 | 세부에서 비급 하나 가져오기 | 가방에 하나 늘고 값 배열이 원본과 같다 |
| 7 | 세부에서 겹쳐지는 아이템 가져오기 | 수량이 그만큼 늘고 칸은 그대로 |
| 8 | 세부에서 화폐 가져오기 | 그 수량만큼 는다 |
| 9 | 빈 칸이 넉넉할 때 모두 가져오기 | 전부 들어가고 결과에 수가 맞게 나온다 |
| 10 | 가방을 가득 채우고 모두 가져오기 | 묻는다. `들어가는 만큼만` → 겹쳐지는 것만 들어가고 나머지는 못 넣은 것으로 나온다. 가방 추가 칸은 그대로 |
| 11 | 10에서 `가방을 늘리고 모두` | 추가 칸이 10칸 단위로 늘고 전부 들어간다 |
| 12 | 깨진 파일, `format`이 다른 파일, 빈 파일을 폴더에 넣는다 | 목록에 "읽을 수 없음"으로 나오고 가져오기 버튼이 없다. 예외 없음 |
| 13 | 파일에 게임에 없는 아이템 번호를 넣는다 | 그 줄만 건너뛰고 알린다 |
| 14 | 삭제(두 번) | 파일이 없어지고 목록에서 사라진다. 한 번만 누르고 다른 동작을 하면 남아 있다 |
| 15 | 저장 후 재시작 | 가져온 아이템이 남아 있다. 다른 세이브에서 가져오는 것은 세이브가 하나뿐이면 "미확인"으로 적는다 |
| 16 | 변경 이력, 배포 구성 | 가져오기가 기록된다. 경고·오류 0, DLL 하나 |
