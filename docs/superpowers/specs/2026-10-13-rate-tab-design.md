# 배율 탭 — 설계 스펙 (묶음 F1)

> 작성일: 2026-10-13 · 대상 게임 버전: v1.2.113.259 · 모드 ID: `sWP6UL`
> 선행 문서: `docs/05-editor-v0.1.md`(13절 세계 탭, 25절 날짜), `docs/06-handoff.md`

## 1. 목적

사용자가 2026-10-13에 요청한 두 가지(프리셋 탭, 배율 탭) 가운데 **배율 탭**만 다룬다. 프리셋 탭은 따로 스펙을 쓴다.

요청 원문:

    2 배율탭 추가
    2-1) 전투중 공법등의 경험치나 이동중 시간 흐름등 배율을 설정할수 있는 상황과 환경을 리서치하고 배율을 적용할수 있는지

사용자가 얻는 것: 수련과 전투로 오르는 수치를 빨리 올리고, 이동해도 날짜가 덜 흐르고, 전투를 빨리 돌리는 스위치를 한 탭에서 켜고 끈다.

## 2. 범위

| 줄 | 단계 | 거는 곳 | 대상 |
|---|---|---|---|
| 수련치 획득 | x1, 2, 5, 10, 100 | `DataUnit.PropertyData.AddExp(Int32 v)` | 플레이어 |
| 전투 중 공법 숙련 | x1, 2, 5, 10, 100 | `DataUnit.UnitInfoData.AddMartialExpInBattle(String id, Int32 exp)` | 플레이어 |
| 이동의 날짜 소모 | x1, 0.5, 0.25, 0.1, 0 | `UnitActionMovePlayer.OnCreate()`의 `costDay` | 플레이어 |
| 전투 속도 | x1, 1.5, 2, 3 | `UnityEngine.Time.timeScale` | 전투 장면 |
| 주는 피해 | x1, 2, 5, 10, 100 | 기존 `BattleService`(세계 탭에서 옮김) | 플레이어 |
| 무적 | 켬/끔 | 기존 `BattleService`(세계 탭에서 옮김) | 플레이어 |

사용자가 고른 것(2026-10-13): 게임에서 걸리는 것을 확인한 항목만 먼저 넣는다. 무적과 피해 배율은 배율 탭으로 옮긴다. 값은 단계 버튼으로 고른다.

### 범위 밖

- 호감도 획득, 영석·아이템 획득, 기예 경험치: 탐침은 걸렸지만 게임이 그 지점을 부르는 상황을 실험에서 만들지 못했다(3.4절). 다음 조사 대상이다.
- 드롭률, 적 능력치 배율, 전투 쿨타임: 지점을 찾지 못했다.
- 전투 밖(인물 화면의 수련·참오)의 공법 숙련: `AddMartialExp`를 직접 부르는 경로가 실험에서 나오지 않았다.
- NPC에게 거는 배율.
- 배율 값의 저장.

## 3. 실측으로 확인한 사실 (2026-10-13)

고정본 세이브(`-Fixture base`)의 회차 `rate1`, `rate2`에서 실험했다. 실험 명령은 `feat/multiplier-research` 브랜치의 `Dev/DevCommandsRate.cs`에 있다(`develop`에 병합하지 않음): `rprobe`, `rrate`, `rstat`, `rzero`, `rtime`, `bcast`, `rmart`.

방법: 후보 메서드에 Harmony 접두 함수를 걸어 호출 수, 플레이어의 호출 수, 인자를 세고, 플레이어의 호출에만 배율을 곱했다.

### 3.1 수련치

| 항목 | 실측 |
|---|---|
| 수련(`UnitActionGridGetExp`) | `PropertyData.AddExp(16)`이 한 번 불린다. 배율 3을 걸자 인자가 48이 됐고 수련치가 6522 → 6570(+48)이 됐다 |
| 전투의 처치 | 적을 처치할 때마다 플레이어의 `AddExp`가 불린다(다섯 번). 고정본 인물과 1레벨 적에서는 인자가 0이었다 |
| 플레이어 구분 | `__instance.Pointer`가 `g.world.playerUnit.data.unitData.propertyData.Pointer`와 같은지로 가린다 |
| 수련치가 꽉 찬 인물 | 수련 자체가 거부된다(`IsCreateAction` 2). 배율과 무관하다 |
| `AddFixExp`, `AddAbilityExp` | 실험 중 한 번도 불리지 않았다 |

### 3.2 전투 중 공법 숙련

| 항목 | 실측 |
|---|---|
| 호출 순서 | 기술을 쓰면 `UnitCtrlPlayer.AddSkillMartialExp(ActionMartialData, Int32 talent, Single growExp)` → `UnitInfoData.AddMartialExpInBattle(id, exp)` → `UnitInfoData.AddMartialExp(id, exp)`. 세 지점의 호출 수가 같았다(8회, 16회) |
| 배율 | `AddMartialExpInBattle`에 5를 걸자 인자 25가 125가 됐고 안쪽의 `AddMartialExp`도 125를 받았다. 절기 숙련 1162 → 1287(+125), 신법 숙련 1414 → 1799(+385 = 77 × 5) |
| **두 번 곱해지는 위험** | `AddMartialExpInBattle`과 `AddMartialExp`는 한 호출의 안팎이다. 둘 다에 걸면 배율이 제곱이 된다. 한 곳에만 건다 |
| 전투 개시 전 | "전투 개시" 버튼을 누르기 전에도 기술이 발동되고 숙련이 오른다 |
| 오르지 않는 기술 | 무예의 숙련(3570)은 실험 내내 그대로였다. 상한으로 보이나 확인하지 못했다 |
| 플레이어 구분 | `__instance.Pointer`가 `g.world.playerUnit.data.unitData.Pointer`와 같은지로 가린다 |

### 3.3 이동의 날짜 소모

| 항목 | 실측 |
|---|---|
| 한 칸의 비용 | `UnitActionMovePlayer.costDay`(Single). 고정본의 위치에서 0.1875 |
| 쌓임 | `UnitActionMovePlayer.GetCurDay(unit)`이 쌓인 값을 준다. 1에 닿으면 `AddResidueDay(1, false)`가 불리고 나머지가 남는다(다섯 칸 뒤 0.9375, 여섯 칸째에 날짜 +1, 쌓인 값 0.125) |
| 배율 | `OnCreate`의 접두 함수에서 `costDay`에 0.5를 곱하자 한 칸에 0.09375가 쌓였다 |
| `GetCurDay`의 반환값을 바꾸는 방법 | 쌓인 값을 읽는 함수라 비용이 아니다. 쓰지 않는다 |
| 날짜 고정과의 관계 | 날짜 고정은 `AddResidueDay`를 건너뛴다(25절). 고정 중에는 이 배율이 날짜에 영향을 주지 못한다 |

### 3.4 전투 속도와 그 밖

| 항목 | 실측 |
|---|---|
| `Time.timeScale` | 전투 중 3으로 쓰면 2초 뒤에도 3이다. 기술을 써도 그대로다. **체감 속도, 게임이 타격 연출(`UnitCtrlPlayer.lastHitTimescaleTime`)에서 값을 되돌리는지, 전투 밖에서의 부작용은 확인하지 못했다** |
| 호감도 `RelationData.AddIntim`, 영석 `WorldUnitData.RewardPropMoney`, 아이템 `WorldUnitData.RewardPropItem(Int32, Int32, Boolean)` | 패치는 걸렸다. 실험 중 불리지 않았다 |
| 패치 설치 | 위 지점 13곳 모두 예외 없이 걸렸다 |
| 화면 밖의 게임에서 전투 조작 | 클릭으로는 공격이 되지 않는다. `UnitCtrlPlayer.CreateSkillAttack(MartialType)`, `CreateStep()`을 직접 부르면 기술이 나간다. 전투 개시는 `(956, 749)`의 `btnStart` |

## 4. 설계

### 4.1 화면

- 새 탭 `배율`을 `세계`와 `안전` 사이에 둔다. 탭 순서: … · NPC · 세계 · **배율** · 안전. 검증 스크립트의 이름은 `Tab10`이 배율, `Tab11`이 안전이 된다.
- 줄 하나가 배율 하나다. 줄에는 이름, 설명 한 줄, 단계 버튼이 있다. 단계 버튼은 누를 때마다 다음 단계로 넘어가고 마지막 다음은 x1이다(기존 피해 배율과 같다). 1배가 아니면 켜진 색이다.
- 맨 위에 `모두 1배로`를 둔다. 무적도 끈다.
- 이동의 날짜 소모 줄은 날짜 고정이 켜져 있으면 설명 자리에 "날짜 고정 중에는 날짜가 흐르지 않습니다"를 보인다. 버튼은 그대로 눌린다.
- 세계 탭에서 전투 보조(무적, 피해 배율)를 뺀다. 순간 이동과 날짜가 남는다.
- 버튼 이름: `RateExp`, `RateMartial`, `RateMove`, `RateSpeed`, `Multiplier`, `God`, `RateReset`. `Multiplier`와 `God`은 기존 이름을 그대로 쓴다(검증이 이름으로 찾는다).

### 4.2 동작 규칙

- 저장하지 않는다. 게임을 켤 때마다 전부 1배, 무적 꺼짐으로 시작한다.
- Harmony 패치는 그 배율을 처음 1배가 아닌 값으로 바꿀 때 그 지점에만 한 번 건다. 건 뒤에는 떼지 않고 값만 본다(날짜 고정과 같다). 한 번도 쓰지 않은 배율은 게임에 아무것도 걸지 않는다.
- 패치를 걸지 못하면 값을 바꾸지 않고 이유를 알린다.
- 접두 함수는 플레이어의 호출만 바꾼다. 안에서 난 예외는 삼키고 원래 값을 통과시키며 로그에 한 줄 남긴다.
- 곱한 값은 `Int32` 범위를 넘으면 최댓값으로 자른다. 인자가 0 이하이면 건드리지 않는다(수련치 감소 등을 키우지 않는다).
- 전투 속도는 전투 장면에 있는 동안만 `Time.timeScale`을 맞춘다. 매 프레임 확인해 값이 다르면 다시 쓰고, 전투 장면을 벗어나거나 x1로 돌리면 1로 되돌린다. 전투 밖에서는 `Time.timeScale`을 건드리지 않는다.
- 값을 바꿀 때마다 변경 이력에 한 줄 남긴다(분류 "배율").
- 1배가 아닌 배율은 화면 위쪽의 상태 표시에 나온다: `수련 x5`, `숙련 x10`, `이동 x0.5`, `속도 x2`. 기존의 `무적`, `피해 x10`, `날짜 고정` 뒤에 잇는다.

### 4.3 구조

| 파일 | 내용 |
|---|---|
| `Services/RateService.cs` (새로) | 배율 값과 단계, `Next…()`(다음 단계로, 결과 문장을 돌려줌), `Reset()`, 패치 설치, 접두 함수, 전투 속도의 프레임 처리 `Tick()`. 화면을 모른다 |
| `Services/WorldService.cs` | `BattleService`는 그대로 둔다(탭만 옮긴다) |
| `UI/Tabs/RateTab.cs` (새로) | 배율 탭. `EditorTab` 상속 |
| `UI/Tabs/WorldTab.cs` | 전투 보조 구역을 뺀다 |
| `UI/EditorWindow.cs` | 탭 목록에 `RateTab` 추가 |
| `UI/EditorHost.cs` | 매 프레임 `RateService.Tick()` |
| `UI/StatusOverlay.cs` | 배율 표시 추가 |

`RateService`의 배율 하나는 이름, 단계 배열, 지금 값, 패치 여부를 가진 작은 객체다. 탭은 그 목록을 돌며 줄을 그린다.

### 4.4 오류 처리

| 상황 | 동작 |
|---|---|
| 패치 실패 | 값을 바꾸지 않는다. "배율: 게임에 연결하지 못해 켜지 않았습니다(…)" |
| 접두 함수 안의 예외 | 원래 값 통과, `[TlToybox] 배율 …` 로그 한 줄 |
| 세계에 들어가기 전(`g.world`가 없음) | 접두 함수가 아무것도 하지 않는다 |
| 전투 장면 판정 실패 | 전투 속도를 걸지 않고 1을 유지한다 |

## 5. 검증

단위 시험이 없으므로 게임 안 검증 스크립트가 시험이다. 검사를 먼저 넣어 실패를 보고, 구현한 뒤 통과를 본다. 고정본 세이브의 회차에서 돌린다.

`tools/research/ui-check.ps1`에 부분 `rates`, `rates-battle`을 더한다.

| 부분 | 보는 것 |
|---|---|
| `rates` | 탭이 그려지고 줄 여섯 개와 `모두 1배로`가 눌린다. 처음에는 패치가 하나도 걸려 있지 않다. 수련치: 경지를 낮춰 수련할 수 있게 한 뒤 x1의 증가량과 x5의 증가량을 비교한다(5배). 이동: x0.5에서 한 칸의 쌓임이 절반, x0에서 0이고 여섯 칸을 걸어도 날짜가 그대로다. 단계가 한 바퀴 돌아 x1로 돌아온다. `모두 1배로`가 전부 되돌린다. 상태 표시와 변경 이력에 나온다. 날짜 고정 중의 안내 문구. NPC에는 걸리지 않는다(개발 명령으로 가까운 NPC의 `AddExp(10)`을 불러 x5에서도 10만 오르는지) |
| `rates-battle` | 전투에 들어가 기술을 발동해 x1과 x5의 숙련 증가량을 비교한다. 전투 속도 x2에서 `Time.timeScale`이 2이고 몇 초 뒤에도 2다. x1로 돌리면 1이다. 무적과 피해 배율이 배율 탭에서 눌린다. 전투에 들어간 채 끝나므로 회차의 마지막에 돌린다 |
| 기존 검사의 수정 | `tabs`(탭 수와 표식), `status`·`status-battle`·`battle`(`God`·`Multiplier`가 `Tab9`가 아니라 `Tab10`에 있다), 안전 탭을 `Tab10`으로 여는 검사 |

전투 뒤 지도로 돌아왔을 때 `Time.timeScale`이 1인지는 전투에서 나오는 방법이 자동화돼 있지 않아 스크립트로 보지 못한다. 구현 중에 나오는 방법을 찾으면 검사에 넣고, 못 찾으면 "확인하지 못한 것"에 적는다.

배포 구성(`-p:DevTools=false`)이 컴파일되는지, 배율 탭이 열리는지 확인한다.

## 6. 확인하지 못한 것 (구현하며 가린다)

- 전투 속도의 체감, 타격 연출과의 충돌, 전투가 끝날 때 게임이 `Time.timeScale`을 어떻게 다루는지.
- 무예의 숙련이 오르지 않은 이유(상한인지).
- 수련치 배율이 돌파 재료·기연 등 다른 경로의 수련치에도 걸리는지(같은 `AddExp`를 지나면 걸린다).
- 이동 비용이 지형·탈것에 따라 달라질 때에도 같은 지점인지.
- 달을 넘길 때 NPC 약 650명의 `AddExp`·이동 호출에 접두 함수가 끼어드는 비용.
