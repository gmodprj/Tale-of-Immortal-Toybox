# 날짜 고정·변경과 가방 칸 — 설계 스펙 (묶음 A)

> 작성일: 2026-10-12 · 대상 게임 버전: v1.2.113.259 · 모드 ID: `sWP6UL`
> 선행 문서: `docs/05-editor-v0.1.md`(13절 세계 탭), `docs/06-handoff.md`

## 1. 목적

사용자가 요청한 추가 기능 여섯 가지를 네 묶음(A 날짜·가방, B UI 구조와 탭별 개선, C 가방 내보내기·가져오기, D 캐릭터 내보내기·가져오기)으로 나눴고, 순서는 A → B → C → D로 정했다. 이 스펙은 **묶음 A**만 다룬다.

- 날짜 고정: 켜 두면 행동을 해도 날짜가 흐르지 않는다(세계 전체 정지).
- 날짜 변경: 게임의 날짜 진행을 그대로 실행하는 방식과, 달력을 직접 지정하는 방식 둘 다.
- 가방 칸: 10칸씩 늘리고 되돌린다.

## 2. 범위

| 기능 | 위치 |
|---|---|
| 날짜 고정 켜기·끄기 | 세계 탭 |
| 날짜 표기를 게임 달력과 같게 | 세계 탭 |
| 실제 진행: +1·+5·+10일, 다음 달 1일로 | 세계 탭 |
| 달력 직접 지정(연·월·일) | 세계 탭 |
| 가방 칸 -10·+10 | 자원 탭 |
| 기존 +1일·+5일의 쓰기 경로 수정 | `WorldService` |

### 범위 밖

- 한 번에 여러 달을 실제로 진행하는 기능(+30일 등). 달이 넘어갈 때마다 게임의 월말 창이 뜨므로 넣지 않는다.
- 날짜 기준 기록(임무 기한, 재사용 대기 등)의 보정.
- 나이·수명만 멈추는 기능.
- NPC의 가방 칸.
- 화면 구조 개편(묶음 B). 이 스펙은 기존 탭에 줄을 추가하는 데 그친다.

## 3. 실측으로 확인한 사실 (2026-10-12)

개발 전용 명령으로 사용자의 세이브에서 실험했고, 실험 뒤 세이브를 실험 전 복사본(`.devremote/save-backup-20261012-datebag`)으로 되돌려 일치를 확인했다. 실험 명령은 `feat/date-bag-research` 브랜치의 `Dev/DevCommandsWorld.cs`에 있다(`develop`에 병합하지 않음).

### 3.1 날짜의 구조

| 항목 | 실측 |
|---|---|
| 달력 변환 | `GameTool.DayToDate(누적 일수)`가 `[연, 월, 일]`을 준다. 0 → 1-1-1, 29 → 1-1-30, 30 → 1-1-30, 31 → 1-2-1, 371 → 1-12-30, 372 → 2-1-1 |
| 한 달 | 31칸(`g.world.run.roundDayMax` 30에 1을 더한 수). 달 안의 위치 0~29가 1~30일이고, 30은 "이번 달의 시간을 전부 사용"한 상태로 30일로 표시된다 |
| 저장값 | `g.data.world.worldDay`. 저장 후 재시작해도 유지된다 |
| 달 안의 경과 | `g.world.run.roundDay`(쓰기 가능). 정상 상태에서 `worldDay % 31`과 같다 |
| 플레이어의 남은 일수 | `unit.data.unitData.residueDay`(쓰기 가능). 정상 상태에서 `roundDayMax - roundDay`와 같다. 세이브를 불러오면 다시 계산된다(어긋난 채 저장한 뒤 재시작하자 17 = 30 - 13) |
| 날짜 소모의 입구 | `WorldUnitBase.AddResidueDay(Int32 day, Boolean isAutoRun)`. 플레이어의 행동은 이 메서드로 날짜를 쓰고, 이 메서드가 `WorldRunMgr.AddDay(day, isAutoRun)`을 부른다 |
| 이동 | `UnitActionMovePlayer`. 한 칸에 0.2~0.33일이 쌓이고 1일이 되면 `AddResidueDay(1, false)` |
| 수련 | `UnitActionGridGetExp`. `AddResidueDay(5, false)` |
| 달 넘기기 | HUD의 날짜 버튼(`btnNextMonth`) → `UIMapMainPlayerInfo.OnSkipMonth()` → 확인 창("이번 달을 건너뛰시겠습니까?") → `AddResidueDay(남은 일수, true)`. 달이 넘어가면 나이가 1 늘고 게임이 자동 저장한다 |
| NPC | 달이 넘어갈 때 다른 단위도 `AddResidueDay`를 거친다(한 번에 약 650회) |

### 3.2 날짜 진행을 막는 실험

| 방법 | 결과 |
|---|---|
| `WorldRunMgr.AddDay`를 Harmony Prefix로 건너뜀(반환값 `false`, `true` 둘 다) | 이동과 수련은 되고 `worldDay`는 그대로다. **그러나 플레이어의 `residueDay`는 줄어든다.** 6일을 막은 뒤 달을 넘기자 다음 달이 7일로 시작했고(217이어야 할 누적 일수가 223), 31일을 막은 뒤에는 두 달이 넘어갔다 |
| 위 상태에서 달 넘기기(`isAutoRun` = `true`)까지 건너뜀 | HUD의 날짜 표기가 혼자 앞서가고 "이번 달의 시간을 전부 사용했습니다" 띠가 남으며 이동이 거부된다(`IsCreateAction` 1) |
| `WorldUnitBase.AddResidueDay`를 Prefix로 건너뜀(플레이어이고 `isAutoRun`이 `false`일 때만, 반환값 `true`) | 이동 6칸, 수련 1회가 정상으로 되고 `worldDay`·`roundDay`·`residueDay`가 모두 그대로다. `AddDay`는 호출되지 않는다. 이어서 달을 넘기자 한 달만 넘어갔다(다음 달 1일, `roundDay` 0, `residueDay` 30) |
| `UIMapMainPlayerInfo.OnSkipMonth`를 Prefix로 건너뜀 | 날짜 버튼을 눌러도 확인 창이 뜨지 않고 화면과 상태가 그대로다. 이동도 계속 된다 |
| 남은 일수가 0인 상태 | 날짜 소모를 막아도 수련은 게임이 거부한다(`IsCreateAction` 1). 이동은 된다 |

### 3.3 달력을 직접 쓰는 실험

| 실험 | 결과 |
|---|---|
| `worldDay`만 씀 | 데이터는 바뀌지만 HUD는 다음 행동 때까지 옛 날짜를 보여 준다 |
| `worldDay`, `roundDay`, 플레이어 `residueDay`를 함께 쓰고 `UIMapMain.uiPlayerInfo.UpdateUI()` 호출 | HUD가 바로 바뀐다. 같은 달 안에서 앞(1일 → 20일), 뒤(20일 → 5일) 모두 확인 |
| 여섯 달 과거로(9월 → 3월 10일) 쓴 뒤 달 넘기기 | 4월 1일이 됐고 `roundDay` 0, `residueDay` 30, 나이 +1. 로그에 예외 없음 |
| `worldDay`와 `roundDay`만 쓴 상태로 저장 후 재시작 | 날짜 유지. 플레이어 `residueDay`는 불러올 때 다시 계산됐다 |

### 3.4 가방 칸

| 항목 | 실측 |
|---|---|
| 용량 | `unit.data.dynUnitData.propGridNum`(`DynInt`). 시험 인물은 기준값 52에 게임이 건 덧셈 12가 붙어 64 |
| 늘리기 | `propGridNum.AddValue(핸들러, 태그)`로 +10을 걸자 `GetGridMaxNum()`이 74가 됐고, 게임 가방 화면이 "가방 용량: 76/74"로 표시했으며, 가득 차 있던 가방에 10종이 더 들어갔다 |
| 유지 | 달이 넘어간 뒤와 `unit.UpdateConf()` 뒤에도 남는다. **저장되지 않는다**(재시작하면 64) |
| 되돌리기 | `DelValue(핸들러)`로 64가 된다. 넘치는 아이템은 그대로 남고(화면 "76/64", 빨간색) 새 아이템만 받지 못한다 |

### 3.5 확인하지 못한 것

- 제작·채집 등 이동과 수련 밖의 행동이 `AddResidueDay`를 거치는지.
- 달 넘기기의 단축키가 `OnSkipMonth`를 거치는지.
- 날짜를 바꿨을 때 날짜 기준 기록(임무 기한, 단약 재사용 대기 `lastUsePropsPillMonth` 등)이 어떻게 되는지.
- `player.AddResidueDay`를 모드 코드에서 직접 부르는 것(게임이 부르는 것을 관찰만 했다).
- `UITipItem.AddTip(String, Single)`의 동작(형식 목록에서만 확인).
- 가방 칸을 수백 칸 늘렸을 때의 화면.
- 게임 가방 화면의 수(시험 세이브 66)와 실제로 더 못 받게 되는 수의 차이. 시험 세이브에서는 "66/64"에서 이미 받지 못했고 +10 뒤 "76/74"에서 멈췄다.

## 4. 결정 사항

- 날짜 고정은 `AddResidueDay`에서 플레이어 행동분만 건너뛴다. `AddDay`는 건드리지 않는다.
- 고정 중에는 게임의 달 넘기기 버튼을 막고 게임 알림으로 이유를 알린다.
- 고정은 게임을 켤 때마다 꺼진 상태로 시작한다(무적과 같은 규칙).
- Harmony 패치는 고정을 처음 켤 때 설치한다. 한 번도 켜지 않으면 게임에 아무것도 걸지 않는다. 설치한 뒤에는 떼지 않고 켜짐 여부만 본다.
- 달력 직접 지정은 세 값(`worldDay`, `roundDay`, 플레이어 `residueDay`)을 함께 쓴다. 날짜 기준 기록은 보정하지 않고 화면에 경고를 적는다.
- 가방 추가 칸은 세이브별로 파일에 기억하고, 세계에 들어올 때마다 다시 건다.
- 가방 칸을 줄이는 것은 0까지 허용한다(넘치는 아이템이 남는 것을 확인했다).

## 5. 설계

### 5.1 구조

| 파일 (`src/ModCode/ModMain/`) | 변경 |
|---|---|
| `Services/TimeService.cs` (새 파일) | 달력 변환, 실제 진행, 달 넘기기, 달력 직접 지정, 날짜 고정(Harmony 패치) |
| `Services/BagService.cs` (새 파일) | 가방 추가 칸의 읽기·쓰기·재적용, 세이브별 저장 |
| `Services/WorldService.cs` | `WorldDay`, `AddDays`를 `TimeService`로 옮기고 지운다. 순간 이동과 `BattleService`는 그대로 둔다 |
| `UI/EditorWindow.cs` | 세계 탭의 날짜 영역, 자원 탭의 가방 줄 |
| `UI/EditorHost.cs` | `EditorHostBehaviour.Update`에서 60프레임마다 `BagService.EnsureApplied()` 호출 |

`TimeService`와 `BagService`는 화면을 모르고, 결과를 문장으로 돌려준다(기존 서비스와 같은 모양).

### 5.2 날짜 고정

    TimeService.Frozen            // 켜짐 여부
    TimeService.SetFrozen(bool)   // 결과 문장을 돌려준다

- 처음 켤 때 Harmony 인스턴스 하나(`TlToybox.time`)로 두 메서드에 Prefix를 건다. 설치가 실패하면 켜지 않고 이유를 돌려준다.
- `WorldUnitBase.AddResidueDay` Prefix: 고정 중이고, 대상이 플레이어(`unitID`가 `g.world.playerUnit`과 같음)이고, `isAutoRun`이 `false`이면 `__result = true`로 두고 원래 메서드를 건너뛴다. 그 밖에는 통과시킨다.
- `UIMapMainPlayerInfo.OnSkipMonth` Prefix: 고정 중이면 `UITipItem.AddTip("날짜 고정 중에는 달을 넘길 수 없습니다. 편집기의 세계 탭에서 고정을 끄세요.", 3f)`를 띄우고 건너뛴다.
- `isAutoRun`이 `true`인 호출은 고정 중에도 통과시킨다. 달 넘기기가 확인하지 못한 다른 경로로 시작되더라도 3.2절의 어긋난 상태가 생기지 않게 하기 위해서다. 그 경우 달은 평소처럼 넘어간다.
- 켜고 끈 것은 변경 이력에 남긴다. 세이브 데이터를 쓰지 않으므로 백업은 하지 않는다.
- 고정 중에는 편집기의 실제 진행 버튼(+N일, 다음 달 1일로)을 비활성으로 두고 이유를 적는다. 달력 직접 지정은 고정 중에도 된다.

### 5.3 날짜 표기와 실제 진행

- 표기: `제 1년 7월 16일 (누적 201일 · 이번 달 남은 날 15)`. 연·월·일은 `GameTool.DayToDate`, 남은 날은 플레이어의 `residueDay`.
- `TimeService.Advance(days)`: `player.AddResidueDay(days, false)`를 한 번 부른다. 남은 날보다 크면 남은 날만큼만 진행하고 그렇게 알린다. 남은 날이 0이거나 날짜 고정 중이면 거부한다. 쓰기 전 백업, 쓰기 뒤 `worldDay`와 `residueDay`를 다시 읽어 기대값과 비교하고 이력에 남긴다.
- `TimeService.OpenSkipMonth()`: 편집기를 닫고 `UIMapMain.uiPlayerInfo.OnSkipMonth()`를 불러 게임의 확인 창을 띄운다. 진행은 게임의 절차다. 지도 화면(`UIType.MapMain`)이 열려 있지 않으면 거부한다.
- 기존 `WorldService.AddDays`는 `g.world.run.AddDay(1, false)`를 직접 불러 플레이어의 `residueDay`를 줄이지 않는다. 3.2절과 같은 종류의 어긋남이므로 위 경로로 대체한다.

### 5.4 달력 직접 지정

    TimeService.SetDate(year, month, day)

1. 입력 범위: 연 1~9999, 월 1~12, 일 1~30.
2. 누적 일수 = `(연-1) × 12 × T + (월-1) × T + (일-1)`, `T = g.world.run.roundDayMax + 1`.
3. 그 값을 `GameTool.DayToDate`에 넣어 입력한 연·월·일이 그대로 나오는지 확인한다. 다르면 쓰지 않는다(게임의 달력 규칙이 달라졌을 때의 안전장치).
4. 백업 후 `worldDay`, `run.roundDay = 일-1`, 플레이어 `residueDay = roundDayMax - (일-1)`을 쓴다.
5. 지도 화면이 열려 있으면 `uiPlayerInfo.UpdateUI()`를 부른다.
6. 세 값을 다시 읽어 확인하고 이력에 `날짜  1년 7월 16일 -> 1년 9월 20일`로 남긴다.

화면에서는 "적용"을 두 번 눌러야 한다. 첫 번째에 "날짜만 바뀝니다. 그 사이의 월말 처리는 일어나지 않고, 임무 기한 같은 날짜 기준 기록은 그대로입니다"를 보여 준다.

### 5.5 가방 칸

    BagService.Extra                 // 현재 세이브의 추가 칸
    BagService.Change(delta)         // ±10. 결과 문장을 돌려준다
    BagService.EnsureApplied()       // 추가 칸이 걸려 있지 않으면 건다

- 범위 0~500, 단위 10.
- 저장: `<TlToybox 폴더>\bag-slots.txt`, 한 줄에 `<playerUnitID>=<추가 칸>`. 세이브의 구분은 `g.data.world.playerUnitID`.
- 걸기: `player.data.dynUnitData.propGridNum.AddValue(핸들러, "TlToybox")`. 값을 바꿀 때는 핸들러를 뗐다가(`DelValue`) 새 값으로 다시 건다. 추가 칸이 0이면 걸지 않는다.
- 재적용: `EnsureApplied`는 세계가 준비됐을 때만 동작한다. 현재 플레이어의 `propGridNum.allAddCall`에 태그 `"TlToybox"`가 없고 추가 칸이 0보다 크면 건다. 세이브에 다시 들어오거나 인물 데이터가 새로 만들어진 경우를 함께 처리한다.
- `Change` 뒤 `GetGridMaxNum()`이 기대한 만큼 변했는지 확인하고 이력에 남긴다. 세이브 데이터를 쓰지 않으므로 백업은 하지 않는다.
- 줄인 뒤 쓰는 칸이 용량보다 많으면 "가방이 넘칩니다. 아이템은 남아 있고, 비우기 전에는 새 아이템을 받을 수 없습니다"를 알린다.
- 파일을 읽거나 쓰지 못하면 값을 바꾸지 않고 이유를 알린다.

모드를 빼거나 파일을 지우면 용량은 게임의 값으로 돌아가고 아이템은 남는다.

자원 탭의 영석 상자에 한 줄 추가:

    가방 66/64 (편집기 추가 +0)   [-10] [+10]

버튼·입력 칸·확인 방식은 기존 `Ui` 도우미와 "두 번 눌러 확인" 관례를 따른다. 배치의 세부는 구현 계획에서 정한다.

## 6. 검증

게임에서 버튼을 눌러 확인한다. 세이브는 백업 → 시험 → 복원 → 일치 확인 순서를 지킨다. 달이 넘어가면 게임이 자동 저장하므로 저장 명령을 쓰지 않은 실행도 복원한다.

| # | 시험 | 기대 |
|---|---|---|
| 1 | 고정 켬 → 이동 6칸, 수련 | `worldDay`·`roundDay`·`residueDay` 불변 |
| 2 | 고정 켬 → HUD 날짜 버튼, 달 넘기기 단축키 | 알림이 뜨고 확인 창이 뜨지 않음. 띠 없음. 이동 가능 |
| 3 | 고정 끔 → 이동 6칸 → 달 넘기기 | 날짜가 진행되고, 한 달만 넘어감 |
| 4 | +1·+5·+10일, 남은 날보다 큰 값, 남은 날 0 | 세 값이 함께 변함. 초과분은 남은 날만큼만. 0이면 거부 |
| 5 | 다음 달 1일로 | 편집기가 닫히고 게임의 확인 창이 뜸. 예 → 다음 달 1일 |
| 6 | 직접 지정: 같은 달 앞·뒤, 다른 달, 다른 해, 범위 밖 입력 | HUD가 바로 바뀜. 범위 밖은 거부. 이후 달 넘기기 정상 |
| 7 | 직접 지정 후 저장 → 재시작 | 날짜 유지 |
| 8 | 가방 +10 두 번, 아이템 지급 | 게임 가방 화면의 용량이 20 늘고 그만큼 더 들어감 |
| 9 | 가방을 늘린 채 저장 → 재시작 | 편집기를 열지 않아도 늘어난 용량이 다시 적용됨 |
| 10 | 가방 -10을 0까지, 넘치는 상태 | 아이템이 남고 안내 문구가 나옴 |
| 11 | 변경 이력 | 고정, 날짜, 가방 변경이 기록됨 |
| 12 | 배포 구성(`-p:DevTools=false`) 빌드, `bin\Release` | 경고·오류 0, DLL 하나 |

3.5절의 미확인 항목은 구현 중 확인되는 대로 05 문서에 적고, 확인하지 못한 것은 "미확인"으로 남긴다.
