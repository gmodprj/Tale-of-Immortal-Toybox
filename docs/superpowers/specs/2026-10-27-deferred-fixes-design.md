# 미룬 사소한 것 묶음 (2026-10-27)

06 문서 8.0절 1번. 사용자 결정(2026-10-27): 고침 1~7과 측정 8·9를 한 묶음으로 한다. 브랜치 `fix/deferred-1027`.

## 1. 의도

앞 묶음들(05 문서 77~83절)의 최종 리뷰가 "미룬 사소한 것"으로 남긴 줄을 정리한다. 새 기능은 없다. 사용자가 보는 변화는 자원 탭 모드 비급 줄의 경지 표기, 원본 없는 줄 숨김, 몇몇 결과 문구뿐이다.

- 목표: 아래 1~7을 고치고, 8·9를 재서 기록한다.
- 범위 밖: 측정 결과가 커도 이 묶음에서 성능 고침은 하지 않는다(값을 기록하고 사용자에게 묻는다). 83.4절의 "화면을 그릴 때마다 후보 계산 반복", "try 밖의 게임 호출", "단계 이름 대응은 캡처로만 확인", 82.3절의 기령 줄 `친밀` 글은 그대로 둔다(문서에 남김).
- 실패로 보는 것: 바뀐 결과 문구 때문에 기존 검사가 깨진 채 남는 것, 고친 길이 게임에서 확인되지 않은 것.

## 2. 고칠 것

### 2.1 전투 영력·집중력 막기의 체인 (80절)

`Services/RateGuards.cs`의 `IsPlayerBattleData`가 `SceneType.battle.battleMap.playerUnitCtrl.data`를 검사 없이 잇는다. 80절의 `InBattleSlot`처럼 하나씩 null을 보고 넘긴다(돌려주는 답은 같고 예외 로그만 사라진다).

### 2.2 자원 탭 모드 비급의 경지 표기 (78절)

`UI/Tabs/ResourcesTab.Books.cs`의 `SkillDetail`이 모드 공법을 늘 `경지 1~10(모드 공법)`으로 적는다. `BookGradeMin~BookGradeMax`(무예/영술은 2~10)로 적는다.

### 2.3 원본 없는 모드 줄 (78절)

모드 줄은 `ModBookFits`만 보고 보이므로, 그 경지에 원본으로 쓸 기본 공법이 없으면(`SourceFor == null`) 꺼진 지급 단추로 남는다. 78절의 사용자 결정("못 만드는 줄은 아예 숨김")대로 `BookShown`이 모드 줄에도 `BlockReason == null`을 보게 한다. 즐겨찾기의 비급 줄은 그대로(보이고 지급은 거절).

- 줄마다 `SourceFor`가 기본 공법 전체를 훑는다. `rperf query`·`rperf tabs`로 기술 서적 그룹 그리기 시간을 고치기 전후로 재고, 50 ms 넘게 늘면 (분류, 경지, basType)별로 결과를 기억한다.

### 2.4 프리셋 폴더 표지와 대경지 이름 캐시 (79절)

- `PresetService.FolderStamp`가 `*.json`만 본다. `.defaults`도 표지에 넣는다(`FileStamp.Of(Dir, "*.json") + "#" + FileStamp.Of(Dir, ".defaults")`). 밖에서 `.defaults`를 지우거나 고치면 다음 열기에 다시 읽는다.
- `AppellationService.majorNames`(대경지 이름 캐시)가 번역 다시 적용(`TranslationService.Apply`, `rloc apply`)과 주 화면 복귀(`ModMain.Destroy`)에 비워지지 않는다. `AppellationService.ForgetNames()`를 두고 두 곳에서 부른다.

### 2.5 설정 파일 로그의 조사 (81절)

`ConfigFile.Io.cs`의 "을(를) 읽지 못했습니다"·"을(를) 저장하지 못했습니다"(로그만). 마지막 글자의 받침으로 을/를을 고르는 순수 함수 `KoreanText.Object(word)`(한글이 아니면 `을(를)`)를 두고 단위 시험을 단다. 다른 곳의 `을(를)`·`은(는)`은 바꾸지 않는다(범위 밖, 화면 글은 그대로).

### 2.6 법보·전승 (82.3절)

- `GradeUpTo`: 되풀이 중 법보를 찾지 못하면 null로 넘어가지 않고 "법보가 사라져 멈췄습니다"로 끝낸다. 끝에서 찾지 못할 때도 같다.
- `GradeUpOne`: 게임이 비율만 깎고 던지면(경지는 그대로) 깎인 비율이 남았다. 경지가 오르지 않았어도 비율이 바뀌었으면 옛 비율로 되돌린다.
- `SetStageNoBackup`·`CloseMax`의 쓰기를 try로 감싸 예외를 결과 문구로 돌린다.
- `RemoveSuit`: `{"suitID":0}`만 적힌 비급을 떼면 "전승 0을(를) 뗐습니다" 꼴이 된다. "빈 전승 기록을 지웠습니다"로.
- `SetSuit` 뒤 확인(`SuitOf == suitId`)이 실패하면 쓴 값이 남았다. 옛 `valuesStr`로 되돌리고 문구에 적는다.
- 경지 10을 넘은 법보(E3의 14)에도 "이미 경지 10입니다"라고 했다. "이미 경지 14입니다(최대 10을 넘음)"처럼 지금 값을 적는다(`GradeUp`·`GradeUpTo`).

### 2.7 대도까지 채우기 (83.4절)

- 다시 만들기가 실패하면 올린 수도 점수를 원래 값으로 되돌린다(`RaisePoints`가 올리기 전 값을 알려 준다). 문구에 "수도 점수는 되돌렸습니다".
- `RaisePoints`가 `EditService.SetAttribute`의 거부 문구를 버린다. 확인 값이 다르면 그 문구를 붙인다.
- 다시 만들기에서 옛 수치(`SetPrefixLevel`) 복사 뒤 `Raws`가 같은지 본다. 다르면 실패로 되돌린다.
- 끼워 넣기 실패의 되돌리기 뒤 값 배열이 옛 것과 같은지 본다. 다르면 "되돌리지 못했을 수 있습니다(공법 탭에서 확인)".
- 다시 만들기 성공 때 장착 칸 번호가 옛 칸과 같은지 본다(심법). 다르면 문구에 적는다.
- 옵션 11개일 때 공법 탭 줄이 `수련 단계 12/12`만 보인다. 스펙 83의 "대도까지 있음"을 붙인다: `수련 단계 12/12 · 대도까지 있음`.
- 긴 까닭 글(160폭 2줄)이 잘린다. 그 글 칸에 Unity `Text.resizeTextForBestFit`(최소 9, 최대 12)를 켠다.

## 3. 잴 것

- 8 (77절): 비급 즐겨찾기 줄이 있을 때 자원 탭 첫 열기(전에 929 ms). `rfav addbook`으로 한 줄 넣은 깨끗한 회차에서 `rperf tabs`.
- 9 (80절): 비급 지급 시간 상한(2초)은 첫 권을 늘 시도한다. 품질 6 한 권이 실제로 몇 초인지 `rbook`을 여러 번 재고(기본 공법·모드 공법) 기록한다.

두 값이 1초를 넘으면 05 문서에 적고 사용자에게 고칠지 묻는다(이 묶음에서는 고치지 않는다).

## 5. 검토자 질문에 정한 것 (내 판단)

- 게임에서 띄우기 어려운 길: 2.4는 확인 길을 만든다 — `rloc apply` 답에 대경지 이름 캐시를 비운 수(`names=n`)를 붙이고, `preset-check files`에 `.defaults`를 밖에서 지운 뒤 다시 열면 기록이 다시 생기는 줄을 더한다. 2.1(전투 장면 전환 순간)과 2.5(입출력 실패 로그)는 흉내 내지 않고 코드 읽기·단위 시험·기존 검사 통과로 친다. 문서에 "게임에서 흉내 내지 않음"으로 적는다.
- 2.6 `SetSuit` 되돌리기: 트레이너 길(`MartialService`의 전승 쓰기, 화면과 `msuit`)의 호출부에서만 한다. 프리셋 적용 길과 `SetSuit` 자체는 그대로 둔다.
- 2.5: 같은 파일의 "만들지 못했습니다" 두 줄도 바꾼다(같은 꼴의 로그).
- 2.3 뒤 `rmods`의 `listed=`가 원본 없는 줄을 세지 않게 맞추고 `modbooks` 검사도 맞춘다.
