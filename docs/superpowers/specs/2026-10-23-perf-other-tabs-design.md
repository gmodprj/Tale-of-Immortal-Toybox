## 2. 목표·비목표·실패

목표

비목표

목표에 못 미칠 때(내 판단): 이 문서가 짚지 않은 무거운 곳을 측정으로 찾으면, 같은 캐시 규칙(언제 비우는지 정함, 게임 상태는 캐시하지 않음)을 지키는 범위에서 고쳐도 된다. 게임 상태를 캐시해야만 줄일 수 있는 곳은 고치지 않고 숫자를 05 문서에 적는다.

## 4. 어떻게 (정한 것)

### 4.1 S7 — 프리셋 탭: 폴더가 같으면 다시 읽지 않는다

`OnShow`·`OnOpen`에서 목록을 비우는 대신, 프리셋 폴더의 파일 목록과 파일마다의 크기·수정 시각으로 만든 표지를 견준다. 같으면 지난 목록을 쓴다. 다르면(넣음·고침·지움) 지금처럼 다시 읽는다. 표지 계산 비용(파일 17개의 메타 읽기)을 재서 0.02초 안쪽인지 본다.

`Draw`가 그릴 때마다 부르는 `PresetService.DefaultsChanged()`(기본 프리셋 파일 전부를 읽어 내장본과 견줌)도 같은 표지를 쓴다: 표지가 같으면 지난 결과를 쓴다(내 판단: 검토자 지적. 이것을 두면 목표를 못 이룬다).

편집기가 프리셋 파일을 쓰는 동작(기본 프리셋 되돌리기, `WriteNewDefaults`)은 쓴 뒤 목록을 비운다(지금 그 동작들이 이미 비우는지 확인하고, 아니면 비우게 한다). `PresetService.Snapshot()`(배운 공법·운명 상태)은 게임 상태라 지금처럼 매번 읽는다.

### 4.2 S8 — 기예 탭: 배운 수와 전체 수를 한 번에 센다

분류마다 "배운 번호 집합"을 세계 자료에서 한 번 만들고(목록 하나 훑기), 서적마다 집합에서 찾는다. 분류별 전체 서적 수는 아이템 카탈로그가 만들어질 때 분류 번호로 한 번 세어 둔다(카탈로그를 비우면 같이 비움). 배운 수는 게임 상태라 탭을 그릴 때마다 센다(집합 만들기는 싸다). 그래서 배우기·잊기 뒤 다시 그리면 바로 맞는 수가 나온다. 줄마다 부르는 `ArtService.BlockReason`(게임의 `IsCreateAction`·`GetStudyErrorTip`)은 게임 상태라 캐시하지 않는다(내 판단). 측정해서 목표를 넘기는 원인이면 05 문서에 숫자를 적는다.

### 4.3 P1·P2 — 도호 탭

- P1: 칩마다 도호 100개를 다시 세지 않고, 그리기 한 번에 칩별 수를 한 번에 센다(검색 콜백의 수 갱신도 같은 함수를 쓴다).
- P2: 자료의 출처(게임 사전 `allAppellationUnits`)는 바꾸지 않는다(내 판단: 출처를 바꾸면 결과가 달라질 수 있다). 그리기 한 번에 플레이어의 `unitID`를 한 번만 읽고, 도호마다의 다른 보유자 목록을 그리기 동안만 캐시해 같은 줄의 보유자 글·두 번 누르기 문구·아래 칸이 같은 목록을 쓴다. 그리기마다 새로 만들므로 낡지 않는다.

### 4.4 S6·P10 — 자원 탭 검색 칸

`OnQuery`에서 검색어로 거른 결과를 한 번 만들고, 그룹 수·종류 수·줄 목록이 같이 쓴다. 칩 폭에 쓰는 "거르기 전의 종류 수"(`Draw`의 `CountByKind(group, new Filter(), owned)`)는 거르기가 비어 보유 상태·가방과 무관하므로 그룹마다 한 번 세어 둔다(아이템 카탈로그가 바뀌지 않는 한 그대로). 줄 목록과 수는 지금과 같아야 한다.

측정: 새 개발 명령 `rperf query <검색어>`가 `OnQuery`와 같은 일을 하고 시간을 돌려준다(전후 비교용).

### 4.5 S9 — `Init`의 모드 행 덮기 (설계 전 실험)

묶음 1에서 `LocalTextIndex.Scan`이 LocalText 72,347행 전부의 `isModExtend`·`ch`·`kr`을 읽는다(1.9초). 모드 행은 한 덩어리로 붙어 있을 수 있고, ch→kr 사전은 바닐라 행 대부분이 쓴다. 실험:
- (가) 모드 행의 위치(첫·끝 순번)가 연속인지, 바닐라 행의 ch→kr 사전이 실행마다 같은지 본다. 같다면 바닐라 부분 사전을 데이터 폴더에 캐시 파일로 두고(게임 판 `v1.2.113.259`와 LocalText 행 수를 표지로), 다음 실행부터 모드 행만 훑는다.
- (나) Il2Cpp 문자열 읽기를 줄이는 길: `kr`을 읽기 전에 `isModExtend`와 `ch`의 한자 여부로 먼저 거른다(이미 그럴 수 있으니 코드로 먼저 확인).
- 결과 같음(`rloc`·`rzhstat`·덤프)이 지켜지는 길만 넣는다. 어느 길도 0.5초 넘게 줄이지 못하면 넣지 않고 숫자를 05 문서에 적는다.

캐시 파일을 두게 되면(내 판단): 표지는 게임 판, LocalText 행 수, **실린 모드 목록**(모드 ID와 판을 줄 세운 것의 해시)이다. 모드 목록이 같으면 같은 모드가 같은 행을 덮으므로 바닐라 부분 사전이 같다. 하나라도 다르면 다시 만든다. Fatury 모드 목록처럼 실행마다 달라질 수 있는 것은 모드 목록에 들어 있으므로 다시 만들 뿐 낡은 번역은 나오지 않는다. 사용자가 지워도 다음 실행에 다시 만든다.

### 4.6 P3·P4

`rperf tabs`와 화면 열기 시간으로 재서 0.05초를 넘을 때만 한 번 부른 결과를 같이 쓰게 한다. 넘지 않으면 05 문서에 숫자만 적는다.

## 5. 검증

- 기준선 회차와 마지막 회차에서 `rperf tabs`(탭마다 첫 열기와 다시 열기), `rperf query`(빈 검색어·한 글자·두 글자), `Init` 로그.
- 캐시가 낡지 않음:
  - 프리셋: 회차 안에서 프리셋 폴더에 파일을 하나 복사해 넣고 탭에 다시 들어가면 줄이 늘고, 지우면 준다. 고치면(크기 변경) 다시 읽는다.
  - 기예: 서적을 배우게 한 뒤(`artstudy` 등 기존 개발 명령) 탭의 "배운 수"가 하나 는다.
  - 도호: `ttlnpcgive`로 다른 인물에게 도호를 준 뒤 그 줄의 다른 보유자가 바뀐다.
- 결과 같음: `rperf dump`, `rloc`, `rzhstat`(4.5를 넣을 때).
- 검사 FAIL 0: `ui-check`의 `tabs`·`items`·`groups`·`appellation-ui`·`translation`, `preset-check`의 `ui`, 기예를 보는 검사(`actions`). 단위 시험(순수 함수가 생기면).
