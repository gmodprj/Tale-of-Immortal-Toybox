# 캐릭터 내보내기·가져오기 — 설계 스펙 (묶음 D)

> 작성일: 2026-10-13 · 대상 게임 버전: v1.2.113.259 · 모드 ID: `sWP6UL`
> 선행 문서: `docs/06-handoff.md`(8.5절), `docs/05-editor-v0.1.md`(28·29절), `docs/superpowers/specs/2026-10-13-bag-export-design.md`

## 1. 목적

현재 캐릭터(플레이어)의 능력치·경지·공법·기예·운명을 이름을 붙여 파일로 내보내고, 내보낸 것을 골라 지금 캐릭터로 가져온다. 전부 한 번에, 항목(구역)별로, 줄 하나씩 가져올 수 있다. 용도는 묶음 C와 같다: 보관, 그리고 다른 세이브·새 인물로 옮기기.

끝난 기준: 7절의 검증이 게임에서 통과한다.

## 2. 범위

사용자와 정한 것(2026-10-13):

| 항목 | 결정 |
|---|---|
| 담는 것 | 능력치 전부(능력치 탭의 다섯 분류: 개인·전투·공법 자질·영근 자질·기예), 경지, 공법, 기예, 선천·후천운명, 역천개명 |
| 대상 | 플레이어만. 내보내기도 가져오기도 플레이어에 한다(편집 대상이 NPC여도) |
| 공법·기예 | 더하기. 지금 가진 것은 그대로 두고 없는 것만 더한다 |
| 선천운명 | 없는 것만 더한다(지금 가진 선천운명은 그대로) |
| 경지 | 게임에서 실험한 뒤 직접 쓴다(3절). 두 번 눌러 확인한다 |
| 위치 | 보관함 탭. 위에 `가방` / `캐릭터` 전환 |
| 파일 | JSON, 내보내기 하나에 파일 하나, 이름은 화면에서 정한다 |

요청 원문(5-1~5-4): JSON 외부 파일, 화면에서 이름 지정, 목록에서 골라 모든 정보를 일괄 가져오기, 세부 목록에서 능력치·경지·공법·기예를 개별로 가져오기.

### 범위 밖

- NPC를 내보내거나 NPC에게 가져오기.
- 가져온 공법의 자동 장착. 장착 여부는 파일에 적어 두고 화면에 보이기만 한다.
- 지금 가진 것을 지우고 파일과 같게 맞추기(공법·기예·운명의 "교체").
- 가방·재화(묶음 C), 호감도·관계, 종문·직위, 임무, 날짜.
- 현재값(체력·영력·기분 등의 지금 수치). 상한과 저장값만 다룬다. 가져온 뒤 채우려면 능력치 탭의 자원 회복을 쓴다.

## 3. 실측으로 확인한 사실 (2026-10-13)

개발 전용 명령으로 사용자의 세이브에서 실험했다(회차 `charx-r1`~`charx-r3`). 끝난 뒤 세이브를 되돌려 일치를 확인했다. 실험 명령은 `feat/char-export-research` 브랜치의 `Dev/DevCommandsChar.cs`와 기존의 `Dev/DevCommandsStage3.cs`(`stats`, `setgrade`, `addexp`)다.

### 경지

| 항목 | 실측 |
|---|---|
| 경지 번호 | `propertyData.gradeID`. 번호는 `g.conf.roleGrade`의 줄이고 대경지(`grade`)·단계(`phase`)·품질(`quality`)을 가진다. 대경지의 초기에는 품질별로 줄이 여럿이다(축기 초기는 4·5·6, 금단 초기는 12~16). 1~22까지 읽었다 |
| `SetGradeID(n)` | `gradeID`가 바뀌고 `exp`가 그 경지의 시작 수련치로 맞춰진다(9 → 13: 11922 → 19842, 13 → 9: 8322). 올리기도 내리기도 된다. 예외 없음 |
| 따라오지 않는 것 | 능력치 저장값과 화면 값(공격 82/106, 방어 50/64, 체력 1791/1934, 영력 614/629), 수명(`life` 2160), 수도 점수(`abilityPoint` 62)는 그대로였다. `UpdateConf()`를 불러도 같다. 운명 목록(`bornLuck`, `addLuck`)도 그대로였다 |
| 수련치 | `propertyData.AddExp(n)`이 n만큼 올린다(8322 → 9322, 반환값 1000) |
| 저장 | 경지 13으로 바꾸고 저장 후 재시작해도 13, 수련치 19842 |

돌파로 얻는 능력치는 경지 번호에서 계산되는 것이 아니라 능력치 저장값에 들어 있다. 그러므로 경지만 가져오면 능력치가 낮은 채로 경지 이름만 바뀐다. 능력치를 함께 가져와야 원래 인물과 같아진다.

### 공법

| 항목 | 실측 |
|---|---|
| 익힌 공법 | `unitData.allActionMartial`(`Dictionary<string, DataUnit.ActionMartialData>`). 키는 고유 번호(`soleID`), 값의 `data`가 `DataProps.PropsData`(공법), `exp`가 숙련 경험치. 시험 세이브는 28개 |
| 값 배열 | `data.values`는 `[2, 0, 수량, 종류, 기술 번호, 경지, 옵션 번호들…, -1, 옵션 품질들…]`이다. 옵션 없는 것은 여섯 칸(`[2,0,1,1,11423,1]`). 옵션 일곱 개인 절기는 `[2,0,1,2,22111,1,3,6,9,5,13,7,11,-1,74,135,12,93,79,599,14]`. 문자열은 28개 모두 없었다 |
| 다시 만들기 | `DataProps.PropsData.New(0, 1, PropsDataType.Martial, 값 배열의 넷째 칸부터)`로 만들어 `unitData.StudyActionMartialProp(props)`로 배우게 하고 `GetActionMartial(soleID).exp`에 숙련 경험치를 쓰면, 값 배열·옵션 번호·옵션 품질·숙련 경험치가 원본과 같다. 옵션 일곱 개 절기, 옵션 없는 무예, 옵션 일곱 개 심법에서 확인. 가방의 비급을 다시 만드는 방법(묶음 C)과 같다 |
| 다른 방법 | `PropsData.NewMartial(종류, 값 배열의 다섯째 칸부터)`도 같은 결과였다. `NewMartial(종류, 넷째 칸부터)`는 깨진 공법(기술 번호 2, 이름 읽기에서 예외)을 만든다. 쓰지 않는다 |
| 저장 | 다시 만든 공법 넷이 저장 후 재시작해도 값·숙련 경험치 그대로 남았다 |
| 수량 0 | 시험 세이브의 한 공법은 값 배열의 수량 칸이 0이었다(`[2,0,0,1,13111,3,…]`, `propsCount` 0). 뜻은 확인하지 못했다 |

### 그 밖 (이전 작업에서 확인한 것)

- 능력치 저장값은 `unitData.propertyData`의 필드이고 `AttributeCatalog.All`에 정의돼 있다. 쓰기는 `EditService.SetAttribute`(게임의 허용 범위 검사, 다시 읽어 확인)다(05 문서 5·14·15절).
- 기예: 단방은 `g.data.world.pillFormulas`(`id`, `exp`, `maxExp`), 그 밖의 다섯 가지는 `g.data.world.allArtistrySkillID`. 조건을 건너뛰고 넣는 것은 `ArtService.ForceLearn`(05 문서 22~24절).
- 운명: 선천은 `propertyData.bornLuck`(배열), 후천은 `propertyData.addLuck`(목록, `id`와 `duration`). 추가는 `LuckService.AddBorn`, `LuckService.Add`. 경지의 난관·돌파 실패 운명은 진행 표식이다(`LuckView.IsSystem`)(05 문서 10·15~17절).
- 역천개명: `g.data.world.playerLog.upGrade`(대경지 번호 → 운명 번호). 정하는 것은 `FateService.Set`이고 도달한 경지만 정할 수 있다(05 문서 18·19절).

### 확인하지 못한 것

- 경지를 직접 바꾼 뒤의 게임 화면(인물 화면의 경지 표시, 경지에 따라 열리는 기능). 실험 중 다른 대화 창이 떠 있어 인물 화면을 캡처하지 못했다. 05 문서 21절의 시험에서는 `SetGradeID`로 올린 뒤 게임의 돌파 화면이 정상으로 동작했다.
- 게임의 돌파 과정이 경지 번호와 능력치 말고 따로 바꾸는 것(해금, 기록)이 있는지.
- 23번 이상의 경지 번호(화신·오도 이후).
- 수량 칸이 0인 공법을 다시 만들었을 때의 차이.
- 선천운명이 게임의 보통 칸 수를 넘었을 때의 동작(05 문서 17절의 미확인과 같다).

## 4. 결정 사항

- 경지 가져오기는 `SetGradeID(파일의 번호)` 뒤에 `AddExp(파일의 수련치 - 지금 수련치)`를 부른다(차이가 양수일 때만). 번호가 게임의 경지 표에 없으면 거부한다. 두 번 눌러 확인하고, 확인 문구와 결과에 "능력치는 따라오지 않는다"를 적는다. 이것은 "경지 ID를 직접 쓰지 않는다"는 규칙(05 문서 3절)의 예외이며 가져오기에서만 쓴다.
- 공법은 `PropsData.New(0, 1, Martial, 값의 넷째 칸부터)` + `StudyActionMartialProp` + `exp`로 넣는다. 넣은 뒤 수가 하나 늘었는지, 이름이 읽히는지, 기술 번호가 같은지 보고, 아니면 바로 지운다(`DelActionMartial`). 기존의 "깨진 공법은 바로 지운다" 규칙과 같다.
- 공법의 "이미 있다"는 같은 기술 번호(`baseID`)를 가진 공법이 있다는 뜻이다. `모두 가져오기`와 구역의 `모두`는 건너뛰고, 줄의 `가져오기`는 있어도 하나 더 넣는다.
- 기예는 `ArtService.ForceLearn`과 같은 방식으로 넣는다(조건을 건너뛴다). 단방은 파일의 `exp`·`maxExp`를 쓴다. 게임의 아이템 표에 없는 번호는 건너뛴다.
- 후천운명은 진행 표식(`IsSystem`), 숨김, 기간이 있는 것(`duration`이 -1이 아님), 역천개명 분류(3)를 내보내지 않는다. 역천개명은 따로 담는다.
- 선천·후천운명은 이미 가진 것(`LuckService.Has`)이면 건너뛴다.
- 역천개명은 지금 도달한 대경지의 것만 `FateService.Set`으로 정한다. 나머지는 건너뛰고 알린다. `모두 가져오기`는 경지를 먼저 바꾸므로 파일의 경지까지 적용된다.
- 능력치는 `EditService.SetAttribute`로 쓴다. 허용 범위 밖이면 그 줄만 거부된다. 이미 같은 값이면 건너뛴 것으로 센다.
- `모두 가져오기`의 순서: 경지 → 능력치 → 선천·후천운명 → 역천개명 → 공법 → 기예.
- 파일 읽기·쓰기는 `Json`을 쓰고, 읽기의 규칙은 묶음 C와 같다: 파일 전체가 틀리면 "읽을 수 없음", 줄 하나가 틀리면 그 줄만 건너뛴다. 게임이 던지는 예외는 줄 단위로 잡아 "못 넣음"으로 센다.

## 5. 설계

### 5.1 파일

위치: `<세이브 뿌리>\TlToybox\exports\character\<파일 이름>.json`. 이름 규칙은 가방과 같다(쓸 수 없는 글자는 `_`, 같은 이름은 `이름 (2)`). UTF-8.

    {
      "format": 1,
      "kind": "character",
      "name": "결정 초기 신환",
      "exportedAt": "2026-10-13 15:30:00",
      "character": "신환",
      "grade": { "id": 9, "name": "결정경 초기", "exp": 11922 },
      "attributes": [
        { "key": "attack", "name": "공격력", "value": 82 }
      ],
      "martials": [
        { "type": 2, "baseId": 22111, "name": "첨권광혈참", "grade": 1, "exp": 1138, "equipped": true,
          "values": [2, 22111, 1, 3, 6, 9, 5, 13, 7, 11, -1, 74, 135, 12, 93, 79, 599, 14] }
      ],
      "arts": [
        { "kind": "연단", "id": 6051011, "name": "화어단 단방", "exp": 0, "maxExp": 100 }
      ],
      "bornLucks": [ { "id": 2804, "name": "…" } ],
      "addLucks": [ { "id": 124, "name": "…" } ],
      "fates": [ { "grade": 2, "id": 700016, "name": "…" } ]
    }

- `attributes`의 `key`는 `AttributeCatalog`의 줄을 가리키는 고정 이름이다(화면의 이름이 바뀌어도 파일이 읽히게). 구현에서 `AttributeDef`에 `Key`를 더한다. 모르는 `key`는 건너뛴다.
- `martials`의 `values`는 머리 세 칸을 뺀 나머지다(가방의 비급과 같다). `type`, `baseId`, `grade`, `name`은 사람이 읽고 화면에 보이기 위한 것이고, 가져올 때는 `values`로 만든 뒤 `baseId`가 같은지 확인하는 데 쓴다.
- `name`들은 가져올 때 쓰지 않는다.
- 읽을 때 `format`이 1이 아니거나 `kind`가 `character`가 아니면 "읽을 수 없음". 구역이 통째로 없으면 그 구역은 빈 것으로 본다.

### 5.2 코드 구조

| 파일 (`src/ModCode/ModMain/`) | 맡는 일 |
|---|---|
| `Services/CharacterExportService.cs` (새 파일) | 내보내기, 목록, 줄·구역·전부 가져오기, 삭제. 결과를 문장으로 돌려준다 |
| `Services/ExportFiles.cs` (새 파일) | 가방과 캐릭터가 함께 쓰는 것: 폴더, 파일 이름 만들기, 같은 이름 피하기, 폴더 안의 `.json`만 지우기, JSON에서 값 꺼내기. `BagExportService`의 해당 부분을 옮긴다 |
| `Services/AttributeCatalog.cs` | `AttributeDef.Key` 추가 |
| `Services/MartialService.cs` | `AddFromValues(unit, values, exp)`: 값 배열로 공법을 만들어 배우게 하고 확인한다 |
| `Services/ArtService.cs` | `ForceLearn`이 단방의 `exp`·`maxExp`를 받을 수 있게 한다 |
| `UI/Tabs/VaultTab.cs` | `가방` / `캐릭터` 전환. 가방 화면은 그대로 |
| `UI/Tabs/VaultCharacterView.cs` (새 파일) | 캐릭터의 목록 화면과 세부 화면 |

    CharacterExportService.Export(name)
    CharacterExportService.List()
    CharacterExportService.ImportAll(pack)
    CharacterExportService.ImportSection(pack, section)      // Grade, Attributes, Lucks, Fates, Martials, Arts
    CharacterExportService.ImportAttribute(pack, index)
    CharacterExportService.ImportMartial(pack, index)        // 있어도 하나 더
    CharacterExportService.ImportArt(pack, index)
    CharacterExportService.ImportBornLuck(pack, index), ImportAddLuck(pack, index), ImportFate(pack, index)
    CharacterExportService.Delete(pack)

쓰기 전에 `SaveBackup.EnsureOnce()`, 쓰기 뒤에 `ChangeLog.Add`. 줄 하나의 가져오기는 한 줄, 구역과 전부는 구역마다 한 줄(넣은 수, 건너뛴 수, 못 넣은 수)을 남긴다. 능력치는 `SetAttribute`가 줄마다 이력을 남기므로 구역 줄을 따로 남기지 않는다.

- 구역 버튼으로 구역을 고른다(한 번에 한 구역). 구역마다 줄의 모양:
  - 경지: 한 줄. 파일의 경지·수련치, 지금의 경지·수련치, `가져오기`(두 번).
  - 능력치: 분류, 이름, 파일의 값, 지금의 값. 같으면 "같음"이고 버튼이 꺼진다.
  - 공법: 종류, 이름, 경지, 숙련 경험치, 옵션 수, 파일에서의 장착 여부, 상태("있음" / "없음"), `가져오기`(있으면 `하나 더`).
  - 기예: 분류, 이름, 상태("배움" / "-"), `가져오기`.
  - 운명: 선천/후천, 이름, 효과, 상태("보유" / "-"), `가져오기`.
  - 역천개명: 대경지, 이름, 효과, 상태("같음" / "다름" / "경지 미달"), `가져오기`.
- 게임에 없는 번호나 읽을 수 없는 줄은 이유를 보이고 버튼을 끈다.

### 5.4 결과 문장 (`ImportAll`)

"경지 결정경 초기로 변경. 능력치 41개 변경(같음 50, 거부 2). 운명 3개 추가(보유 9). 역천개명 2개 지정. 공법 12개 추가(있음 16). 기예 7개 추가(배움 48)." 못 넣은 것이 있으면 구역마다 이름을 다섯 개까지 덧붙인다.

## 6. 작업 순서

1. `ExportFiles`로 공통 부분을 옮기고 가방 검사(`vault`)가 그대로 통과하는지 본다.
2. `AttributeDef.Key`, `MartialService.AddFromValues`, `ArtService`의 단방 값.
3. `CharacterExportService`의 내보내기와 읽기 + 캐릭터 목록 화면.
4. 가져오기(줄, 구역, 전부) + 세부 화면.
5. 전체 검증, 문서(05 문서 30절, 인계 문서), 병합, 설치.

## 7. 검증

`session.ps1` 회차 안에서, `tools/research/ui-check.ps1`에 `charvault`·`charvault-restart` 부분을 더해 한다. 검사가 만드는 파일은 이름이 `uicheck-`로 시작하고 검사가 지운다.

| # | 시험 | 기대 |
|---|---|---|
| 1 | 이름을 적고 내보내기 | 파일이 생기고 목록 맨 위에 나온다. JSON으로 읽히고 구역 여섯이 있다. 공법 수 = 익힌 공법 수, 능력치 수 = 능력치 정의 수 |
| 2 | 빈 이름, 같은 이름, 쓸 수 없는 글자 | 가방과 같다 |
| 3 | 가방 쪽으로 전환했다가 돌아오기 | 가방 목록에는 캐릭터 파일이, 캐릭터 목록에는 가방 파일이 나오지 않는다 |
| 4 | 능력치 하나를 바꾼 뒤 그 줄 가져오기 | 파일의 값으로 돌아오고 줄이 "같음"이 된다 |
| 5 | 능력치 구역 모두 | 바꿔 둔 값들이 모두 파일의 값이 된다. 결과의 수가 맞는다 |
| 6 | 경지를 다른 번호로 바꾼 뒤 경지 가져오기 | 한 번 누르면 묻고, 두 번째에 파일의 경지와 수련치가 된다 |
| 7 | 공법 하나를 잊은 뒤 그 줄 가져오기 | 공법 수가 하나 늘고, 새 공법의 값 배열과 숙련 경험치가 파일과 같다 |
| 8 | 공법 구역 모두 | 없는 것만 늘어난다. 한 번 더 누르면 늘지 않는다 |
| 9 | 있는 공법의 `하나 더` | 같은 기술이 하나 더 생긴다 |
| 10 | 기예 하나를 잊은 뒤 가져오기 / 구역 모두 | 다시 배운 것으로 나온다 |
| 11 | 후천운명 하나를 지운 뒤 가져오기, 선천운명 하나를 지운 뒤 가져오기 | 다시 생긴다. 가진 것은 건너뛴다 |
| 12 | 역천개명을 다른 것으로 바꾼 뒤 가져오기 | 파일의 것으로 돌아온다. 경지를 낮춘 상태에서는 "경지 미달"로 건너뛴다 |
| 13 | 여러 가지를 바꾼 뒤 `모두 가져오기` | 두 번 눌러야 하고, 끝나면 경지·능력치·공법 수·기예·운명이 내보낼 때와 같다 |
| 14 | 손으로 고친 파일: 없는 능력치 `key`, 범위 밖의 값, 없는 경지 번호, 값이 모자란 공법, 없는 기예·운명 번호, 숫자 자리에 글자 | 그 줄만 건너뛰거나 거부하고 이유를 알린다. 예외 없음 |
| 15 | 깨진 파일, `kind`가 `bag`인 파일을 캐릭터 폴더에 | "읽을 수 없음", 가져오기 버튼 없음 |
| 16 | 삭제(두 번), 목록을 본 뒤 밖에서 지워진 파일 | 가방과 같다 |
| 17 | 저장 후 재시작 | 가져온 경지·능력치·공법이 남아 있다 |
| 18 | 변경 이력, 버튼 콜백의 예외, 모드의 경고, 배포 구성 | 기록된다. 예외·경고 0, DLL 하나 |
| 19 | 기존 검사(`vault`, `wrap`, `tabs` 등) | 그대로 통과 |

## 9. 위험

| 위험 | 대응 |
|---|---|
| 경지만 가져와 능력치가 경지에 맞지 않는 인물이 됨 | 확인 문구와 결과 문장에서 알린다. `모두 가져오기`는 능력치를 함께 가져온다 |
| 경지를 직접 바꾼 뒤 게임의 어떤 화면이 어긋남(미확인) | 세이브 백업이 먼저 만들어진다. 검증에서 인물 화면을 캡처해 본다. 발견하면 05 문서에 적는다 |
| 다른 게임 버전에서 만든 파일의 값 배열이 깨진 공법을 만듦 | 넣은 뒤 이름과 기술 번호를 읽어 보고, 읽히지 않으면 바로 지운다 |
| 능력치를 낮은 값으로 덮어씀(예: 새 인물의 파일을 원래 인물에 가져옴) | `모두 가져오기`와 경지는 두 번 눌러 확인한다. 세부 화면이 파일의 값과 지금의 값을 나란히 보인다 |

| `ExportFiles`로 옮기다 가방 내보내기가 깨짐 | 작업 순서 1번에서 `vault` 검사를 먼저 돌린다 |
