# 도호(칭호) 관리 설계 (2026-10-15)

## 1. 목적

사용자 요청(2026-10-15): G2(창작마당 모드 연동)를 미루고 "도호관리 기능부터". 사용자가 도호(道号)·칭호라고 답했다. 게임의 한국어 글은 칭호(appellation)를 "도호"라고 부른다(예: 고정본 인물의 "영단도인").

사용자가 고른 것:

- 쓰임: 내 인물에게 원하는 도호 붙이기, 갖고 있는 도호 정리(빼기·장착 바꾸기). NPC의 도호 관리와 전체 보유 현황 보기는 고르지 않았다.
- '제일' 도호(한 사람만 가지는 것)를 다른 NPC가 가졌으면 그 NPC에게서 옮겨 온다.
- 지금 경지에 맞지 않는 도호도 주되, 다음 돌파 때 잃는다고 알린다.
- 게임의 "도호 획득" 창은 띄우지 않는다.
- 자리: 새 도호 탭.

## 2. 실측 (인계 문서 8.3d절, 회차 `apl-1015a`·`b`, 고정본, 실험 브랜치 `feat/appellation-research`)

| 항목 | 실측 |
|---|---|
| 설정 표 | `g.conf.appellationTitle` 100줄. 쓰는 칸: `id`, `className`(첫 값이 분류), `name`·`desc`·`tips`·`gainDesc`(`GameTool.LS`로 읽는 글), `roleEffect`, `lossType`, `dropType`·`dropValue`. 효과는 `g.conf.roleEffect`(`effectType`, `value`) |
| 분류(`className` 첫 값) | 101 지역 제일 X수 60개(영녕~팔황, 무기·영근별), 102 풍류 5, 103 괴수 6, 104 산재 5, 105 예상 2, 106 소요 5, 107 영단 4, 108 영보 4, 109 만법천존 1, 110 어계천존·단금쉬옥 2, 112 참요천존 1, 2601~2605 승선대회 결말 5 |
| '제일' 도호 | `lossType` 1인 60줄(분류 101 전부). 한 사람만 가진다는 게임 규칙이지만 `AddAppellationID`는 막지 않아 두 사람이 가지게 되고, 달을 넘겨도 게임이 정리하지 않았다 |
| 잃는 경지 | `dropType` 1이면 `dropValue`가 그 경지(1 연기 … 10 등선). 11은 잃지 않는다. 판정은 돌파 때(`WorldUnitAppellationDrop1.OnRoleUpGrade`)이고 달을 넘길 때는 하지 않는다 |
| 저장 자료 | `unitData.appellationTitle`: `appellationItems`(`id`, 얻은 `month`), `equipAppellationID`. 인물별 이름 칸이 없다 |
| 실행 중 관리자 | `unit.appellation`(`WorldUnitAppellationMgr`): `AddAppellationID(id) : bool`, `DelAppellationID(id, isAddLog)`, `EquipAppellationID(id)`, `UnequipAppellationID(id)`, `allAppellations`, `allEquipAppellations`. 정적 `WorldUnitAppellationMgr.allAppellationUnits`(번호 → 가진 인물 목록, 넣고 빼면 바로 바뀐다) |
| 주기 | 아무 번호나 받는다(경지 밖, 다른 인물이 가진 '제일' 도호도 `True`). 하나 넣을 때마다 게임의 "도호 획득" 창(`GetTaoist`)이 하나씩 뜬다. 장착한 것이 없으면 넣은 도호를 장착한다 |
| 빼기 | `DelAppellationID(id, false)`. 장착한 것을 빼면 장착이 빈다. 저장 후 다시 켜면 게임이 가진 것 하나를 장착한다 |
| 장착 | 한 번에 하나. 효과는 장착했을 때만 든다(어계천존 `talent_1_40` → 오성 90 → 130) |
| 저장 | 넣기·빼기·장착이 저장 후 재시작해도 남는다 |
| 게임 화면 | 인물 화면의 초상 아래 도호를 누르면 `TaoistSelect`(획득한 도호 / 도호 획득 가능, `도호 교체`)가 열려 가진 것 가운데서 바꿀 수 있다 |

## 3. 결정

### 3.1 화면 (도호 탭)

탭 줄의 16번째 탭(`Tab15`, 제목 "도호"). 플레이어 전용이다(편집 대상을 따르지 않는다).

    [장착 중] 영단도인 — 장착하면 자신의 단약을 다른 수선자들이 더 좋아한다.   [장착 해제]
    분류 [전체 100][가진 것 3][제일 60][풍류 5][괴수 6][산재 5][예상 2][소요 5][영단 4][영보 4][천존 4][결말 5]
    도호명 [검색 칸] [가진 것만] [초기화]
    상태 | 도호명 | 분류 | 잃는 경지 | 다른 보유자 | 버튼
    [아래 칸: [번호] 이름 · 분류 / 효과 / 얻는 법 / 설명 / 보유자 / 경지·이야기 안내]

- 맨 위 장착 칸: 장착한 도호의 이름과 효과 글(`tips`), `장착 해제`. 장착한 것이 없으면 "장착한 도호가 없습니다".
- 분류 칩: `전체`, `가진 것`, 그리고 `className`의 묶음. 제일(101), 풍류(102), 괴수(103), 산재(104), 예상(105), 소요(106), 영단(107), 영보(108), 천존(109·110·112, 단금쉬옥 포함), 결말(2601~2605). 표에 이 밖의 분류 번호가 있으면 `기타` 칩에 모은다. 칩의 수는 검색어와 `가진 것만`을 반영한다.
- 검색 칸은 이름의 일부 또는 번호(공백·기호 무시, 다른 탭과 같은 방식). `가진 것만`은 가진 도호만. `초기화`는 검색어·`가진 것만`·분류를 처음으로.
- 표의 열:
  - 상태: ★ 장착, ● 가짐, - 없음.
  - 도호명, 분류(칩 이름).
  - 잃는 경지: `dropValue`의 경지 이름(예: "결정경"), 잃지 않으면 "-". 지금 대경지가 그 값 이상이면 경고 색으로 "결정경 · 다음 돌파".
  - 다른 보유자: 플레이어를 뺀 보유자. '제일' 도호는 그 이름, 그 밖은 "NPC n명", 없으면 "-".
  - 버튼: 가진 것이면 `빼기`와 `장착`(장착 중이면 `장착 중`, 꺼짐). 갖지 않은 것이면 `주기`. 다른 인물이 가진 '제일' 도호면 `<이름>에게서 가져오기`.
- 줄이나 이름을 누르면 아래 칸에 `[번호] 이름 · 분류`, 효과(`tips`), 얻는 법(`gainDesc`), 설명(`desc`), 보유자, 그리고 해당하면 경지 안내("결정경 이상이라 다음 돌파 때 잃습니다")와 이야기 안내(3.2).
- 이름 바꾸기는 넣지 않는다(저장 자료에 인물별 이름이 없다). NPC의 도호는 다루지 않는다.

### 3.2 동작 규칙

- 주기: `SaveBackup.EnsureOnce()` 뒤 `AddAppellationID(id)`. 넣은 뒤 저장 자료를 다시 읽어 가졌는지 확인한다. 장착한 것이 없어 게임이 바로 장착했으면 결과에 "장착됨"을 붙인다.
- '제일' 도호(`lossType` 1)를 다른 인물이 가졌으면 버튼이 `<이름>에게서 가져오기`가 되고 두 번 눌러 확인한다(`Confirm`). 그 인물들에게서 먼저 `DelAppellationID(id, false)`로 빼고 나에게 넣는다. 결과: "도호 주기: 팔황 제일권수 (관산에게서 옮김)".
- 경지 밖: 막지 않는다. 지금 대경지가 잃는 경지 이상이면 결과에 "결정경 이상이라 다음 돌파 때 잃습니다"를 붙인다. 경지 탭의 경지 올리기와 프리셋 적용도 도호를 다시 판정하므로 그때도 잃는다(문서에 적는다).
- 획득 창: 편집기에서 준 도호는 "도호 획득" 창(`GetTaoist`)을 띄우지 않는다. 방법(넣은 뒤 닫기 또는 열리지 않게 막기)은 구현 첫 단계에서 게임으로 정한다. 막을 수 없으면 멈추고 사용자에게 알린다.
- 이야기 도호: 결말 다섯(2601~2605, 효과가 그 이야기의 인물을 불러낸다)과 단금쉬옥(2500)은 주기를 허용하되 아래 칸과 결과에 "이야기와 묶인 효과라 확인하지 못했습니다"를 붙인다.
- 빼기: 두 번 눌러 확인한다(게임이 붙인 것을 지우는 동작, 편집기 공통 규칙). `DelAppellationID(id, false)`. 장착 중이었으면 결과에 "장착이 비었습니다"를 붙인다. 갖지 않은 도호는 거부한다.
- 장착·해제: 가진 도호만 `EquipAppellationID(id)`. 해제는 `UnequipAppellationID(id)`. 갖지 않은 도호의 장착은 거부한다.
- 변경 이력: 바꿀 때마다 한 줄. 항목 `도호 <이름>(<번호>)`, 이전·이후는 `없음`·`가짐`·`장착`. '제일' 도호를 옮기면 그 NPC 이름으로 한 줄(`가짐` → `없음`)을 더 적는다. 쓴 뒤 다시 읽어 다르면 "(재조회 불일치)"가 붙는다(공통 규칙).
- 게임이 던지는 예외는 서비스 안에서 잡아 결과 문장에 이유를 쓴다.
- 도호를 본 NPC가 말을 거는 대화는 게임의 동작이라 그대로 둔다.

## 5. 검증

단위 시험이 없으므로 게임 안 검사가 시험이다. 검사를 먼저 넣어 실패를 보고, 구현한 뒤 통과를 본다. 모두 고정본 회차(`-Fixture base`)에서 한다. 고정본 인물은 결정(대경지 3)이고 영단도인(2001)을 장착했다. 관산(`synXcL`)이 팔황 제일권수(1404)를 가졌다.

| 검사 | 보는 것 |
|---|---|
| `appellation`(서비스) | 풍류도인(1502)을 주면 가진 목록에 들고 장착은 2001 그대로, 획득 창이 열리지 않고 변경 이력이 한 줄. 1404를 주면 보유자가 플레이어 하나, 관산에게서 빠지고 이력이 두 줄. 영녕 제일도수(1001)를 주면 결과에 "다음 돌파". 1502 장착 → 장착 1502, 해제 → 없음. 장착한 것을 빼면 장착이 빔. 갖지 않은 도호 빼기와 장착은 거부. 어계천존(2111) 장착 → 오성 +40. 버튼 콜백 예외 없음 |
| `appellation-restart` | 저장 후 다시 켜도 가진 것·옮겨 온 1404가 그대로 |
| `appellation-ui`(화면) | `Tab15`와 장착 칸, 칩 수의 합 100(`전체`), 검색과 `가진 것만`으로 줄이 줄어듦, 줄의 상태 글, 1001의 잃는 경지 경고, 1404의 버튼이 "관산에게서 가져오기"이고 한 번 눌러서는 옮겨지지 않고 두 번째에 옮겨짐, 빼기도 두 번, 아래 칸의 효과·얻는 법·보유자, 장착 칸이 바뀜, 예외·모드 경고 없음 |
| 회귀 | 탭 16개에 맞춘 `base`·`tabs`, `wrap`, `items` |
| 빌드 | 개발·배포 구성 모두 경고·오류 0, DLL 하나 |

- 사용자가 직접 확인할 것: 실제 마우스로 누르기, 한글 입력기로 검색, 게임의 인물 화면에서 바뀐 도호가 보이는지.

## 8. 확인하지 못한 것, 위험

- "도호 획득" 창을 막는 방법(3.2). 구현 첫 단계에서 정하고, 안 되면 멈춘다.
- 이야기 도호(결말 다섯, 단금쉬옥)를 이야기 없이 줬을 때 효과가 드는지, 전투에서 문제가 없는지.
- NPC에게서 '제일' 도호를 뺀 뒤 도전·순위 같은 게임 흐름에 다른 영향이 있는지(보유자 목록이 바로 갱신되는 것만 봤다).
- 이 탭으로 탭 줄이 가득 찬다. 다음 탭은 탭 줄을 다시 짜야 한다.
