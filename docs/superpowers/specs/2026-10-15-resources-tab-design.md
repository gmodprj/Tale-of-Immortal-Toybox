# 자원 탭 개편 설계 — 즐겨찾기와 용도별 분류 (2026-10-15)

## 1. 목적

사용자 요청(2026-10-15, 원문):

    1 문서확인
    2 자원탭에 즐겨찾기기능 추가
    3 자원탭 카테고리 분류 재조정 및 개선 (분류/UI/UX)
    4 스팀 모드 반영 및  및 모드 한글화, 공법 모드의 경우 이 모드에서 해당 공법 문서 획득 여부

이 스펙은 요청 2·3(묶음 G1)을 다룬다. 요청 4는 묶음 G2(창작마당 모드 연동)로 따로 설계한다(9절). 요청 1의 결과는 인계 문서에 남긴다(8절).

사용자가 고른 것:

- 지금 자원 탭의 불편한 점: 분류가 직관적이지 않다, 세부 분류가 너무 많고 이름이 겹친다, 같은 종류가 흩어져 있다, 화면 배치·조작이 불편하다(넷 다).
- 즐겨찾기: 아이템과 수량을 함께 저장한다. 모든 세이브에 공통이다. 즐겨찾기 보기에 "모두 지급"을 둔다.
- 분류: 게임 분류표 대신 편집기가 정한 용도별 그룹.
- 화면: 왼쪽에 세로 그룹 목록, 오른쪽에 종류·필터·표·설명.

## 3. 결정

### 3.1 용도 그룹

- 게임의 세부 분류 번호(`className`)를 편집기가 정한 (그룹, 종류)로 옮긴다. 표는 `Services/ItemGroups.cs` 하나에 둔다(4절).
- 표에 없는 번호는 `기타` 그룹에 넣는다. 종류 이름은 게임 분류 이름(`ItemCatalog.CategoryName`)이고, 이름이 없으면 `분류 <번호>`다. 창작마당 모드가 새 분류 번호로 아이템을 추가하면 여기에 들어간다.
- 의복(304)은 의복 표(`g.conf.clothItem`)의 `sex`로 종류 `남`(1)·`여`(그 밖)를 나눈다. 의복 표에 없는 의복은 `여`가 아니라 그룹 `의복`의 종류 `그 밖`에 넣는다.
- 한 아이템은 그룹 하나, 종류 하나에만 들어간다.
- 정렬: 그룹 안에서는 4절 표의 종류 순서, 같은 종류 안에서는 게임 표 순서(`_allConfList`의 순서). `기타`의 종류는 세부 분류 번호 순서이고, 이름이 같은 종류는 하나로 합친다(합친 종류의 번호는 가장 작은 번호).

### 3.2 즐겨찾기

- 표의 줄 맨 앞의 별 버튼: ☆(없음)을 누르면 그 아이템을 **지금의 지급 수량**(`AmountBar.Get("item")`)으로 넣는다. ★(있음)을 누르면 뺀다. 두 번 누르기 확인은 하지 않는다.
- 왼쪽 맨 위 `★ 즐겨찾기 n`. 이 보기는 넣은 순서대로 보인다.
  - 줄마다 수량 칸(`NumberField`)이 있다. Enter로 저장한다. 1~999999(`AmountBar.Max`) 밖이면 저장하지 않고 안내한다.
  - 줄의 `지급`은 저장된 수량으로 준다(위쪽 지급 수량이 아니다).
  - 검색·품질·보유 중만 필터가 이 보기에도 걸린다. 종류 칩은 없다.
  - `모두 지급`: 지금 보이는(걸러진) 줄 가운데 게임에 있는 아이템을 저장된 수량으로 차례로 준다. 두 번 눌러 확인한다(`Confirm`). 결과 문장: `즐겨찾기 모두 지급: 넣음 n, 못 넣음 m(이름, …)`. 성공은 보유 수가 수량만큼 늘었는지로 판정한다.
- 게임에 없는 번호(모드를 뺀 경우 등): 파일에서 지우지 않는다. 줄에 `게임에 없는 아이템 (<번호>)`로 보이고 지급 버튼이 꺼진다. ★로 뺄 수 있다. 모드를 다시 넣으면 원래대로 보인다.
- 즐겨찾기를 넣고 빼거나 수량을 바꾸는 것은 게임 값을 바꾸지 않으므로 변경 이력(`ChangeLog`)에 남기지 않는다. 결과는 메시지 칸에만 보인다. 지급은 지금처럼 이력에 남는다.

### 3.3 즐겨찾기 파일

- 위치: `ChangeLog.DataDir`의 `favorites.txt`(`%USERPROFILE%\AppData\LocalLow\guigugame\guigubahuang\TlToybox\favorites.txt`). 세이브와 무관하다.
- 형식: UTF-8, 한 줄에 `<아이템 번호> <수량>`. 빈 줄과 `#`로 시작하는 줄은 건너뛴다.
- 읽기: 처음 쓸 때 한 번 읽는다. 해석할 수 없는 줄과 이미 나온 번호의 줄은 건너뛰고 그 수를 센다. 수량이 범위 밖이면 범위 끝으로 맞춘다. 건너뛴 줄이 있으면 자원 탭에 처음 들어올 때 한 번 `즐겨찾기 파일에서 읽지 못한 줄 n개를 건너뛰었습니다`를 보이고 `MelonLogger.Warning`에도 남긴다.
- 쓰기: 바꿀 때마다 파일 전체를 다시 쓴다. `favorites.txt.tmp`에 쓰고 바꿔치기한다(`File.Replace`, 원래 파일이 없으면 `File.Move`). 건너뛴 줄이 있던 파일을 처음 덮어쓰기 전에 원래 파일을 `favorites.txt.bak`으로 남긴다.
- 쓰기에 실패하면 메모리의 목록을 바꾸기 전 상태로 되돌리고 `즐겨찾기: 파일에 쓰지 못했습니다(<이유>)`를 보인다.

- 오른쪽(x=180, 폭 1124):

- 표의 번호는 게임 분류표(`ItemType.json`)에 있는 것 가운데 아이템이 있는 것과, 아이템이 없어도 이름이 같은 계열인 것(510 진화, 537, 601 씨앗, 603 표차, 619, 625, 627 호신부, 630 오악진형도, 649 신비한 편지)을 넣었다.
- 실행 중의 게임 표가 사본과 다를 수 있다. 모드 없는 게임에서 `기타`가 0개인지 검사가 확인한다(7절). 0이 아니면 그 번호를 표에 넣는다.

## 7. 검증

단위 시험이 없으므로 게임 안 검사가 시험이다. 검사를 먼저 넣어 실패를 보고(회차를 코드 고치기 전에 연다, 인계 6절), 구현한 뒤 통과를 본다. 모두 고정본 회차(`-Fixture base`)에서 한다.

| 검사 | 보는 것 |
|---|---|
| `ui-check.ps1 -Part items`(고침) | 그룹 `ResGroupPill` → 종류 `ResKind1`(회복) → 검색 `보원단` → 품질 `ResQuality1` → 목록이 한 줄(`ItemName1011011`, 6품 보원단). 보유 중만을 켜면 보유에 따라 0개 또는 1개, 지급한 뒤에는 1개. `ItemGive<번호>`로 지급하면 `count <번호>`가 지급 수량만큼 오른다. 목록 이동(`ItemTableNext` 등)과 휠은 지금처럼 |
| `-Part groups`(새) | `rgroups`: `기타` 0개, 그룹 개수의 합이 `전체`와 같다. 화면: `전체`의 수와 `ResGroupPill`의 수가 `rgroups`와 같다. 검색어를 넣으면 왼쪽 개수가 바뀌고 지우면 돌아온다. `ResGroupCloth`의 종류가 `남`·`여`다 |
| `-Part favorites`(새) | 즐겨찾기 비어 있음 → 지급 수량 10으로 `ResStar<번호>` → `rfav`에 `<번호> 10`, 별이 ★. `ResGroupFav`에 그 줄 하나. `ResAmount<번호>`에 25를 쓰고 Enter → `rfav`에 25. `ItemGive<번호>` → 보유 +25. 둘째 아이템을 넣고 `ResAllGive` 두 번 → 두 아이템 모두 저장 수량만큼 오르고 결과 문장이 `넣음 2, 못 넣음 0`. ★로 하나 빼기 → `rfav`에 하나. 파일이 원자적으로 바뀌었는지(`.tmp`가 남지 않음) |
| `favorites-restart`(`-Restart` 뒤) | 즐겨찾기가 남아 있다(번호와 수량) |
| `-Part favorites-corrupt`(새) | 검사가 파일에 깨진 줄 둘과 게임에 없는 번호(예: 99999999) 하나를 섞어 쓴 뒤 `-Restart` → 자원 탭에 들어가면 "읽지 못한 줄 2개" 안내. 게임에 없는 줄은 `게임에 없는 아이템 (99999999)`로 보이고 `ItemGive99999999`가 꺼져 있다. 하나를 넣으면 `favorites.txt.bak`이 생긴다 |
| 회귀 | `base`, `tabs`, `wrap`, `numbers`, `history`가 통과한다. `artifact-check.ps1`의 `ItemQuery` 입력 시험이 그대로 된다 |
| `session.tests.ps1` | 새 시험을 포함해 모두 통과 |
| 빌드 | 개발 구성과 배포 구성(`-p:DevTools=false`)이 모두 컴파일된다 |

- 검사는 앞 검사의 화면 상태를 물려받는다(인계 6절). 각 부분은 시작할 때 `ResGroupAll`, `ResClear`, 검색 칸 비우기로 상태를 만든다.
- 사용자가 직접 확인할 것(도구로 못 하는 것): 실제 마우스로 별 누르기, 한글 입력기로 검색, 화면이 보기 좋은지.

## 10. 확인하지 못한 것, 위험

- 4절의 개수는 게임 표 사본으로 센 것이다. 실행 중의 수는 검사(`rgroups`)로 확인한다.
- `단약`(~1290)은 그룹 하나로는 크다. 종류와 품질로 줄여 보는 것을 전제로 했다. 사용자가 써 보고 더 나누자고 하면 4절의 표만 고친다.

- 모두 지급으로 수십 종류를 한 번에 줄 때 한 프레임에 걸리는 시간은 재지 않았다.
