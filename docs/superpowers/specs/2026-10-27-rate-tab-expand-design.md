# 배율 탭 확장 (묶음 6 나, 2026-10-27)

12 문서 7절 6번 (나), 11 문서 4절 3번. 사용자 결정(2026-10-27): 배율 탭을 **분류 칩**으로 나눈다(두 열·한 화면 줄이기 대신). 브랜치 `feat/rate-tab-expand`(예정), 설계 전 실험은 실험 브랜치 `feat/rate2-research`(병합하지 않음).

## 1. 의도

배율 탭에 넷을 더한다: 지도 속도(전투 밖 게임 속도), 전투 이동 속도, 호감 변화, 정력 소모. 지금 14줄이라 18줄이 되면 줄 높이가 42로 줄어 설명이 잘리므로, 줄을 분류 칩으로 나눠 줄 높이 64와 설명 글을 지킨다.

- 목표: 새 줄 넷이 게임에서 걸리고, 기존 14줄이 칩으로 옮겨져도 동작·검사가 그대로다.
- 범위 밖: 트레이너 표의 다른 미반영 기능(쿨타임 넓히기, 일격필살 등), 호감 감소(`AddHate`) 배율, NPC 쪽 배율.
- 실패로 보는 것: 칩을 바꾸면 켜 둔 배율이 보이지 않아 사용자가 켠 줄을 잊는 것(→ "켜 둔 것" 칩과 기존 화면 위 표시), 기존 검사가 칩 때문에 깨진 채 남는 것.

## 2. 설계 전 실험 (회차 `r2-a`~`d-1027`, 고정본, `-Exclude 2814696167`)

## 3. 화면

- 탭 머리(지금과 같음): `배율` 글, `모두 1배로`, 안내 글.
- 그 아래 칩 줄: `성장`·`시간·속도`·`전투`·`관계·소모`·`켜 둔 것`. 칩 글 뒤에 그 칩에서 1배가 아닌 줄 수를 붙인다(예 `전투 2`). 고른 칩은 편집기를 닫았다 열어도 기억한다(세션 동안만, 메모리).
- 칩 아래 줄은 지금 꼴(이름, 값 단추, 설명), 줄 높이 64.
- 칩별 줄:
  - 성장: 수련치 획득, 전투 중 공법 숙련, 비급 학습 진도
  - 시간·속도: **지도 속도**(새), 전투 속도, 이동의 날짜 소모, 수련·학습의 날짜 소모
  - 전투: **전투 이동 속도**(새), 기술 쿨타임, 신기 쿨타임, 영력 소모, 집중력 소모, 주는 피해, 받는 피해, 무적
  - 관계·소모: **호감 변화**(새), **정력 소모**(새), 아이템 소모
  - 켜 둔 것: 위 줄 가운데 1배가 아닌 것(무적은 켜짐). 없으면 "켜 둔 배율이 없습니다".
- 줄 단추 이름은 지금 것을 그대로 둔다(`RateExp`, `Multiplier`, `God` …). 새 줄은 `RateMapSpeed`·`RateBattleMove`·`RateIntimGain`·`RateEnergyCost`. 칩은 `RateGroup0`~`RateGroup4`.

## 4. 새 배율

모두 저장하지 않고 게임을 켤 때·세이브를 떠날 때 끈다(기존 규칙, `ModMain.ResetState`). 화면 위 켜 둔 것 표시와 변경 이력에 남는다(기존 `RateService.Next`).

| 줄 | 단계 | 거는 법 |
|---|---|---|
| 지도 속도 | x1·1.5·2·3 | 세계에 있고 전투 장면이 아닐 때 매 프레임 `Time.timeScale`을 맞춘다. 0(게임 정지)은 건드리지 않는다. 끄거나 전투에 들어가면 1로(전투 속도 줄이 전투를 맡는다). 지도 속도와 전투 속도가 서로의 값을 되돌리지 않게 "누가 걸었나"를 따로 기억한다 |
| 전투 이동 속도 | x1·1.5·2·3 | 전투의 플레이어 `data.moveSpeed`에 `AddValue` 처리기(base×(배수−1))를 건다. 전투 단위가 바뀌면(새 전투) 다시 건다(쿨타임의 `cooldownUnit`과 같은 꼴). 끄면 뗀다 |
| 호감 변화 | x1·2·5·10 | `RelationData.AddIntim` 접두: 플레이어가 주체이거나 대상인 호출의 양수 value만 곱한다. 게임 대화는 양쪽으로 부르므로 나→상대·상대→나 모두 빨라진다. 감소(음수·`AddHate`)는 그대로(내 판단: "호감이 빨리 오른다"가 뜻이고 미움을 키우는 것은 반대 효과). NPC끼리의 호출과 편집기 NPC 탭(`SetIntim`)에는 걸리지 않는다 |
| 정력 소모 | x1·0.5·0.25·없음 | 매 프레임 플레이어 정력이 줄었으면 줄어든 만큼 × (1−배율)을 돌려준다(없음이면 전부). 늘어난 것은 그대로. 편집기가 능력치 탭에서 정력을 쓰면 그 프레임은 돌려주지 않는다(기준 값을 다시 잡는다) |

## 5. 검증

- 단위 시험: 칩 분류(18줄이 정확히 한 칩씩, "켜 둔 것" 거르기)와 정력 돌려주기 계산(순수 함수)을 링크해 시험.
- 개발 명령(develop로): `rtrack start|read`(실험의 `r2track`), `rintim <unitID> <값>`(플레이어 relationData.AddIntim 직접, 전후), `renergy`(정력과 돌려준 합), `rmove`(전투 플레이어 moveSpeed value/base).
- 검사 `ui-check.ps1`의 새 부분 `rates2`: 칩 다섯과 수, 줄이 칩마다 맞게 보임, 새 줄 넷 단추와 설명, "켜 둔 것" / `rates2-map`: 지도 속도 x3에서 이동이 빨라지고 끄면 1 / `rates2-battle`: 전투 이동 속도 값, 새 전투에서 다시 걸림, 끄면 원래 값 / `rates2-life`: 호감 x5 직접 호출, 정력 없음에서 훔치기 뒤 정력 그대로, x0.5면 반.
- 기존 검사(`rates`·`rates-battle`·`combat`·`itemuse`·`mpnone`·`base`·`tabs`)가 칩을 먼저 고르도록 맞추고 FAIL 0.
- 호감은 게임 대화 길로 확인한다(`UnitActionRoleChat`을 만들고 선택지 `goOptionItem`을 넘김, 실험의 `r2chat`을 개발 명령 `rchat`으로). 양쪽 값이 x1보다 크게 오르는지 본다. 전투 이동의 실제 걷는 빠르기는 도구로 잴 수 없어(가상 키로 인물이 움직이지 않음) 값 확인까지만 하고 사용자 확인 목록에 넣는다.
