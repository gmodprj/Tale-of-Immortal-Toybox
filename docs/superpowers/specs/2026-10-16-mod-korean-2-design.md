# 창작마당 새 모드 8개 한글화(K) 설계 (2026-10-16)

## 1. 목적

사용자 요청(2026-10-16) 4번 "추가모드 한글화". 2026-10-16에 설치한 창작마당 모드 8개(05 문서 45절)가 더한 글 766행이 번역표에 없어 중국어로 보인다(43절의 `ch` 대체). 사용자의 결정: "모든 장면이 한글화되어야 한다" — 766행 전부를 번역한다.

## 2. 실측

- 회차 `ws-1017a`(45절)에서 `rloc`가 `rows=59 applied=59 fallback=516`, `rloc dump written=766`. 입력 `.devremote\untranslated-20261016.txt`(키<TAB><TAB>중국어).
- 766행의 내용: 중국어 25,518자. 열 자 이하 506행, 40자 이하 98행, 120자 이하 100행, 400자 이하 60행, 그 넘는 것 2행(절색방 안내문 1,181자, 종족 기술 설명 465자). 키 머리: `jsT_*` 235(팔황 절색방 화면 글), `skill_*` 98·`role_*` 74(종족 틀·종족 확장·용족), `spriteSub*` 41·`spriteTalent*` 19·`spriteArt*` 5(요도희), `s_*`·`effect_*` 34, `drama_*` 17, `bhjsbText*` 15, `yaodao*` 7, 그 밖에 20. 영어 플래그 `0lkK4v`(`exists`)가 하나 섞여 있다(43절처럼 번역하지 않는다).
- 데이터 폴더 `translations\mods.txt`는 지금 59행(43절 판). `TranslationService.EnsureFile`은 파일이 있으면 내장본을 풀지 않는다(43절 결정. 사용자가 고친 파일을 지키려고). 그래서 새 판의 번역을 받으려면 사용자가 파일을 지워야 한다.

## 3. 결정

### 3.1 범위

- 766행 가운데 `0lkK4v`를 뺀 765행을 모두 번역해 `src/ModCode/ModMain/Translations/mods.txt`에 덧붙인다(59 + 765 = 824행). 모드마다 `# <창작마당ID> <한국어 이름>` 주석 줄로 묶는다.
- 번역표의 원본은 그 파일 하나다(43절 스펙 부록 A처럼 다시 적지 않는다. 824행은 문서에 두기엔 크다).
- 모드 자체의 이름(게임 모드 화면의 `g.mod.modDatas[].name`)은 LocalText가 아니라 범위 밖(43절과 같음).

### 3.2 번역 규칙

- 자리 표시 `$…$`·`&…&`·`{…}`·`<…>`와 `\n`은 원문 그대로 둔다. 합치기 전에 스크립트가 원문과 번역의 자리 표시 집합이 같은지 검사한다(다르면 멈춘다).
- 게임 용어는 게임 본체의 한국어 표기와 기존 59행을 따른다(유혈·작열·내상·영력·경지 이름·속성 이름). 인명·종족명·지명은 한자 음독(진룡·청룡·응룡, 풍리희). 브랜드성 이름(절색방·준걸방·진자각)도 음독.
- 짧은 이름(열 자 이하)은 이름답게 짧게, 설명은 뜻이 통하는 한국어 문장으로. 중국어 투의 감탄·광고 문구는 뜻만 옮긴다.

### 3.3 코드 변경: 내장본의 새 키를 파일에 덧붙인다 (`TranslationService.EnsureFile`)

- 파일이 없으면 지금처럼 내장본을 풀어 둔다(`풀어 둠`).
- 파일이 있으면 내장본을 읽어, 내장본에는 있고 파일에는 없는 키의 줄을 파일 끝에 덧붙인다. 앞에 `# 덧붙임 yyyy-MM-dd: 내장본의 새 키 n` 주석 한 줄. 사용자가 고친 줄은 그대로다(같은 키는 건드리지 않는다). 돌려주는 글은 덧붙인 것이 있으면 `덧붙임 n`, 없으면 `있음`.
- 파일 쓰기에 실패하면 `읽기 실패 …`로 지금처럼 `Apply`가 이어진다(사전은 파일에서 읽은 것만).
- 로그 `[TlToybox] translations: file=덧붙임 n rows=… applied=… fallback=… unused=… broken=…`. `check-lib.ps1`의 `ModWarnings`는 `translations: ` 머리의 정보 줄을 이미 경고로 세지 않는다.
- 효과: 배포 DLL을 설치하고 게임을 켜면 첫 `Init`에서 765행이 데이터 폴더 파일에 저절로 들어간다. 사용자가 파일을 지울 필요가 없다. 사용자가 고친 줄은 남는다.

### 3.4 검사 (`ui-check.ps1 -Part translation`)

- 기존 검사의 수치를 바꾼다: `rows=59`→`824`, `rows=61`→`826`(깨진 줄·모르는 키 검사), `applied=59`→`824`. `fallback`은 `[01]` 그대로(영어 플래그 1).
- 새 검사 둘: (1) 파일을 "주석 한 줄 + `skill_name_middle984555698<TAB>열염장2`"로 바꾸고 `rloc apply` → `file=덧붙임 823 rows=824 applied=824`, 파일에 새 키(`role_race_long0`)가 있고 고친 줄(`열염장2`)이 남아 `rloc key skill_name_middle984555698`이 `ls=열염장2`. (2) 그 상태에서 다시 `rloc apply` → `file=있음`(덧붙일 것이 없음). 끝에 원본 복원.
- 새 모드의 키 몇 개를 `rloc key`로 본다: `role_race_long0`(진룡), `jsT_*` 가운데 화면 제목 하나, `spriteSub*` 하나.
- `rloc dump`는 `written=1`(영어 플래그만) 그대로.

## 4. 코드

- `src/ModCode/ModMain/Services/TranslationService.cs`: `EnsureFile`에 덧붙이기. 내장본 파싱은 `Load`와 같은 규칙(`#`·빈 줄 무시, 탭 앞이 키). 덧붙이는 줄은 내장본의 줄 그대로.
- `src/ModCode/ModMain/Translations/mods.txt`: 765행 추가.
- `tools/research/ui-check.ps1`: `translation` 부분의 수치와 새 검사 둘.
- 번역 합치기·검사 스크립트는 작업용(스크래치)이고 저장소에 넣지 않는다.

## 8. 확인하지 못한 것, 위험

- 번역은 제가 중국어를 읽고 썼다. 게임 화면에서 자리 표시가 풀린 문장 전체(특히 절색방의 긴 안내문, 종족 기술 설명)는 사용자 확인 항목.
- 캐릭터 생성의 종족 선택과 절색방 화면은 회차에서 열지 못한다(새 게임·주성 진입). 키 단위(`rloc key`)로만 본다.
- `Apply()`가 `Init`마다 55,267행을 도는 비용은 그대로(사전이 824행이어도 사전 조회는 해시).
- 덧붙이기는 "키가 없는 줄"만 더하므로, 사용자가 줄을 지워 번역을 끈 키는 다음 실행에 다시 들어온다(끄려면 빈 글로 두는 편). 05 문서에 적는다.
