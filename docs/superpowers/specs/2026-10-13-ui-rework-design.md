# 화면 구조 정리와 탭별 UI/UX 개선 — 설계 스펙 (묶음 B)

> 작성일: 2026-10-13 · 대상 게임 버전: v1.2.113.259 · 모드 ID: `sWP6UL`
> 선행 문서: `docs/06-handoff.md`(8.3절), `docs/05-editor-v0.1.md`, `docs/superpowers/specs/2026-10-12-date-bag-design.md`(묶음 A)

## 1. 목적

묶음 A → B → C → D 가운데 **묶음 B**다. 두 가지를 한다.

- 사용자가 직접 쓰면서 불편하다고 고른 네 영역을 고친다: 검색과 목록, 수량·증감 입력, 창 자체, 결과·안내 문구.
- 묶음 C·D(가방·캐릭터 내보내기·가져오기)의 여러 단계 화면(목록 → 세부 → 개별 가져오기)을 얹을 수 있게 화면 코드를 나눈다. 지금은 창 전체가 `UI/EditorWindow.cs` 한 파일(1,371줄)이고 상태 변수 50여 개가 한 클래스에 있다.

끝난 기준: 지금 되는 기능이 모두 그대로 동작하고, 화면 코드가 창의 틀·공통 부품·탭별 파일로 나뉘며, 6절의 검증이 게임에서 통과한다.

## 2. 범위

사용자와 정한 것(2026-10-13):

| 항목 | 결정 |
|---|---|
| 고칠 영역 | 검색과 목록, 수량·증감 입력, 창 자체, 결과·안내 문구 — 넷 모두 |
| 창 | 크기(1500x1000)는 유지. 제목 줄을 끌어 이동, `접기`로 제목 줄만 남김 |
| 탭 | 9개의 이름과 순서 유지. 편집 대상이 적용되는 능력치·공법·운명에 표시 |
| 함께 넣는 작은 기능 | 가방 칸 한 번에 지정, 변경 이력 전체 보기 |
| 코드 구조 | 탭별 클래스 + 공통 부품. 다시 그리기 방식은 유지하고 목록만 따로 다시 그린다 |
| 목록 | 스크롤로 통일하고, 긴 목록에는 `처음`·`이전`·`다음`·`끝` 버튼을 함께 둔다 |

### 범위 밖

- 아이템·영석 줄이기(요청 6번의 후보로 남긴다).
- 창 크기 변경, 큰 창·작은 창 전환, 탭 재구성.
- `Services/`의 동작 변경. 이 스펙은 `UI/`와 `Safety/ChangeLog.cs`의 읽기 함수 하나만 건드린다.
- 묶음 A의 최종 검토에서 남긴 다섯 가지(`docs/06-handoff.md` 7절).
- 묶음 C·D의 화면 자체. 이 스펙은 그 화면이 얹힐 자리(탭의 하위 화면)만 만든다.

## 3. 실측으로 확인한 사실 (2026-10-13)

개발 전용 명령으로 사용자의 세이브에서 실험했다(회차 `uirework-r1`). 끝난 뒤 세이브를 시험 전 복사본으로 되돌려 일치를 확인했다. 실험 명령은 `feat/ui-rework-research` 브랜치의 `Dev/DevCommandsUi.cs`에 있다(`develop`에 병합하지 않음).

### 3.1 게임 UI의 캔버스와 정렬

| 항목 | 실측 |
|---|---|
| 게임의 뿌리 캔버스 | `g.ui.canvas`. `ScreenSpaceCamera`, `planeDistance` 100, 정렬 층 `Default`, 게임 오브젝트의 층 5 |
| UI 카메라 | `g.ui.uiCamera`(이름 `Camera`). 직교, `depth` 10, `cullingMask` 32(층 5만) |
| 화면 크기 맞춤 | `g.ui.canvasScaler`: `ScaleWithScreenSize`, 기준 1920x1080, `screenMatchMode` `Expand` |
| 층 | `UILayer`마다 자식 캔버스가 있고 정렬을 따로 준다(`overrideSorting`). `UI` 0, `UITop` 10000, `Guide` 10100, `Loading` 10200, `Window` 10300, `Mask` 10400, `FullEffect` 10500, `TempUI` -1 |
| 화면 하나 | 층 아래에 자기 캔버스(`UIBase.canvas`)를 갖고 `UIBase.sortingOrder`로 정렬된다. 지도 화면(`MapMain`)이 0이고, 그 위에 연 인물 화면(`PlayerInfo`)이 20이었다. 간격은 `UIMgr.UIIntervalSorting`(정적, 20) |
| 층의 맨 위 값 | `g.ui.GetLayerTopSort(UILayer.UI)`가 지도만 있을 때 0, 인물 화면을 열자 20, 닫자 0 |
| 화면별 층 | `PlayerInfo`·`NPCInfo`·`UpGrade`·`FateFeature`·`MonthLog`·`MonthLogBig`·`DramaDialogue`·`DramaFortuitous`·`TextInfo`·`PropSelect`는 `UI`. `CheckPopup`·`CheckPopup1`은 `Window`. `SkyTip`은 `UITop`. `Loading`은 `Loading` |

### 3.2 편집기 캔버스를 게임 화면 사이에 끼우기

지금 편집기는 `ScreenSpaceOverlay`, 정렬 30000이다. 이 방식은 카메라가 그린 것 위에 덧그리므로 게임의 어떤 창보다도 위에 나온다(돌파 결과, NPC 대화, 월말 기록이 편집기 뒤에 뜨던 원인).

| 실험 | 결과 |
|---|---|
| 편집기 캔버스를 `ScreenSpaceCamera`로, `worldCamera`를 `g.ui.uiCamera`로, `planeDistance`·`sortingLayerID`·뿌리 오브젝트의 층을 게임 캔버스와 같게, `sortingOrder` 10 | 편집기가 지도 화면 위에 정상으로 그려진다. 표, 스크롤 영역(`RectMask2D`), 글자 모두 이전과 같다. 자식 오브젝트의 층은 0인 채로 두어도 그려졌다(뿌리의 층만 맞추면 된다) |
| 그 상태에서 탭 버튼 클릭, 표 스크롤 | 버튼이 눌리고 스크롤 이벤트가 표에 간다 |
| 그 상태에서 인물 화면을 연다(정렬 20) | 인물 화면이 편집기 위에 그려지고, 편집기 자리의 클릭이 인물 화면으로 간다 |
| 인물 화면을 닫고 확인 창을 연다(정렬 10300) | 확인 창이 편집기 위에 그려지고, 확인 창의 바탕이 편집기로 가는 클릭을 막는다 |

### 3.3 끌기

| 실험 | 결과 |
|---|---|
| 창에 `EventTrigger`를 붙이고 `BeginDrag`·`Drag`·`EndDrag` 항목을 추가(`entry.callback.AddListener(new Action<BaseEventData>(...))`) | 항목 3개가 등록됐다 |
| `ExecuteEvents.Execute`로 `beginDragHandler` 1회, `dragHandler` 4회(한 번에 +50, -25 픽셀), `endDragHandler` 1회 | 콜백이 1·4·1회 불렸다. 콜백 안에서 `data.Cast<PointerEventData>().delta`를 창의 `anchoredPosition`에 더하자 (60,-60) → (260,-160)이 됐다 |
| 옮긴 뒤 탭 버튼이 있던 자리 + (200,100)을 조회 | 탭 버튼이 잡힌다(창 전체가 함께 움직였다) |
| 반대 방향으로 10번에 나눠 되돌림 | (59.99997,-60). 누적 오차가 생긴다 |

### 3.4 입력 칸

| 실험 | 결과 |
|---|---|
| `InputField.onEndEdit.AddListener(new Action<string>(...))` | 등록된다 |
| 입력 칸을 고르고(`EventSystem.SetSelectedGameObject`, `ActivateInputField`) 게임 창에 Enter 키 메시지를 보냄(`win.ps1 -Do key -Vk 0x0D`) | `onEndEdit`이 불리고, 그 콜백 안에서 `Input.GetKeyDown(KeyCode.Return)`이 `true`다. `wasCanceled`는 `false` |
| 같은 상태에서 글자 키 메시지를 보냄(`-Vk 0x41`) | 입력 칸의 글이 `a`가 되고 `onValueChanged`가 불린다. 게임 창이 화면 밖에 있어도 된다 |

글자 키가 입력 칸에 들어가므로 자동 검증에서 실제 타자 경로를 쓸 수 있다(이전에는 개발 명령으로 `text`를 직접 넣었다).

### 3.5 확인하지 못한 것

- 실제 마우스로 끄는 동작(도구가 보낸 이벤트로만 시험했다).
- 한글 입력기로 글자를 조합하는 동안의 `onValueChanged`.
- 포커스를 잃어서 온 `onEndEdit`(Enter 없이)에서 `Input.GetKeyDown(KeyCode.Return)`이 `false`인지. Unity의 규칙으로는 그렇다.
- 전투 화면, 주 화면(세이브 진입 전), 로딩 중의 `g.ui.uiCamera` 상태와 카메라 방식 편집기의 표시.
- 지도 화면 안에 정렬 값을 따로 가진 자식 캔버스가 있는지(시험에서는 편집기 정렬 10이 지도 화면 전체를 덮었다).

## 4. 결정 사항

- 편집기 캔버스는 게임과 같은 카메라 방식으로 그리고, 정렬은 "맨 앞으로 가져올 때의 `UI` 층 맨 위 값 + 10"이다. 게임 화면의 정렬이 20 간격이므로 겹치지 않는다.
- UI 카메라를 쓸 수 없으면(`g.ui`·카메라가 없거나 꺼져 있음, 게임 캔버스가 카메라 방식이 아님) 지금 방식(덧그리기, 30000)으로 그린다.
- 끌기는 `EventTrigger`로 받는다. 위치는 끌기 시작 위치 + 누적 이동량으로 계산해 정수로 맞춘다(3.3절의 누적 오차).
- 숫자 칸의 적용은 `onEndEdit` 안에서 Enter 키를 확인해 구분한다. Enter 없이 포커스를 잃으면 적용하지 않는다.
- 검색은 `onValueChanged`로 즉시 건다. 검색어가 바뀌면 탭 전체가 아니라 **목록만** 다시 그린다(탭을 다시 그리면 입력 칸이 지워져 포커스를 잃는다).
- 목록은 보이는 줄만 만든다. 전체 높이만큼의 스크롤 영역에 화면에 걸친 줄만 놓고, 첫 줄 번호가 바뀔 때만 줄을 다시 만든다.
- 켜 둔 기능의 표시는 편집기와 별개의 덧그리기 캔버스에 둔다(전투 중이나 게임 창이 편집기를 가렸을 때도 보여야 한다).
- 수량 단위는 쓰는 곳마다 따로 기억하고, 게임을 다시 켜면 기본값으로 시작한다(지금과 같음).
- 검증 스크립트는 버튼을 좌표가 아니라 이름으로 찾는다.

### 5.2 창의 틀

**캔버스와 앞뒤 순서**

    EditorWindow.Raise()     // 맨 앞으로: 방식을 정하고 정렬 = GetLayerTopSort(UILayer.UI) + 10
    EditorWindow.IsCovered   // UI 층의 맨 위 값이 편집기의 정렬보다 크다

- 열 때 `Raise()`를 부른다. 그 뒤에 열리는 `UI` 층의 게임 화면은 정렬이 더 커서 편집기 위에 뜬다. `UITop` 이상의 층(확인 창, 로딩)은 항상 위다.
- 열려 있는 동안 `Tick`에서 `UI` 층의 맨 위 값을 본다. 그 값이 맨 앞으로 가져올 때의 값보다 작아졌으면(그때 있던 게임 화면이 닫힘) 정렬을 새 맨 위 값 + 10으로 낮춘다. 그러지 않으면 다음에 열리는 게임 화면이 편집기 뒤에 뜬다.
- 단축키(`Insert`): 닫혀 있으면 열고, 열려 있는데 `IsCovered`이면 `Raise()`만 하고, 그 밖에는 닫는다.
- 카메라 방식을 쓸 수 없으면 덧그리기 30000으로 그리고, 이 경우 `IsCovered`는 항상 `false`다.

**제목 줄** (높이 52)

    TlToybox 편집기   편집 대상: 신환 (플레이어) 결정 초기  [플레이어로]            [접기] [닫기]

- 제목과 편집 대상을 한 줄로 합친다. 내용 영역의 위쪽이 104에서 64로 올라간다.
- 편집 대상이 NPC이면 이름을 강조색으로 보이고 `플레이어로` 버튼을 켠다. 지금 능력치 탭 아래에 있는 `대상: 플레이어로` 버튼은 없앤다.
- 제목 줄의 빈 곳이 끌기 손잡이다. 창의 위치는 1920x1080 기준 좌표로 다루고, 제목 줄의 세로 전체와 가로 200 이상이 화면 안에 남도록 범위를 제한한다.
- 끌기를 마치면 위치를 `<TlToybox 폴더>\config.txt`의 `window=<x>,<y>` 줄에 쓴다. 다른 줄(`hotkey=` 등)은 그대로 둔다. 읽을 때 값이 없거나 범위 밖이면 기본 위치 (60,60) 또는 범위 안의 가장 가까운 자리로 한다.
- `접기`: 탭 줄, 내용, 결과 영역을 숨기고 창 높이를 제목 줄만큼으로 줄인다. 버튼은 `펼침`으로 바뀐다. 접힌 상태는 기억하지 않는다(다음에 열면 펼친 상태).

**탭 줄**

- 왼쪽 세로 줄, 9개. 편집 대상이 적용되는 탭(능력치·공법·운명)은 버튼 왼쪽 가장자리에 강조색 세로 띠를 붙인다.
- 탭을 바꾸면 결과 문구와 확인 대기를 지우고, 떠나는 탭의 `OnHide()`와 들어가는 탭의 `OnShow()`를 부른다.

**결과 영역**

    EditorWindow.Say(text)   // 결과 문구를 보이고 현재 탭을 다시 그린다

- 창의 맨 아래, 세 줄까지 줄바꿈된다. 넘치면 잘린다.
- 새 문구가 오면 배경을 잠깐(약 0.6초) 밝게 했다가 되돌린다. `Tick`이 시간에 따라 색을 바꾼다.

**함께 쓰는 상태**

    EditorWindow.Player / Target / IsTargetNpc
    EditorWindow.SetTarget(unitId)   // null이면 플레이어. 모든 탭의 OnTargetChanged()를 부른다
    EditorWindow.SelectedNpcId       // NPC 탭에서 고르고 세계 탭의 "선택한 NPC에게 이동"이 쓴다
    EditorWindow.SwitchTab(index)

지금은 NPC 탭의 `능력치 편집` 버튼이 다른 탭의 상태 변수 여섯 개를 직접 지운다. 바뀐 뒤에는 `SetTarget`이 알리고 각 탭이 자기 선택과 하위 화면을 스스로 지운다.

### 5.3 켜 둔 기능 표시

- 무적(`BattleService.God`), 피해 배율(`BattleService.Multiplier`가 1보다 큼), 날짜 고정(`TimeService.Frozen`) 가운데 켜진 것을 한 줄로 보인다. 예: `무적 · 피해 x4 · 날짜 고정`.
- 화면 위쪽 가운데의 작은 상자. 덧그리기 캔버스(30000)에 두고 클릭은 받지 않는다(`GraphicRaycaster` 없음).
- 켜진 것이 없거나 세이브에 들어가지 않았으면 숨긴다. `Tick`이 30프레임마다 상태를 읽어 갱신한다.
- 편집기를 한 번도 열지 않았으면 만들지 않는다(세 기능 모두 편집기에서만 켤 수 있다).

### 5.4 탭의 기반

    abstract class EditorTab
        string Title            // 탭 이름
        bool UsesTarget         // 편집 대상이 적용되는 탭인지
        void Render(content)    // 틀이 부른다. 하위 화면이 있으면 맨 위의 것을, 없으면 Draw를 그린다
        abstract void Draw(content)
        void Push(title, draw)  // 하위 화면을 쌓는다
        void Pop()              // 한 단계 돌아간다
        virtual void OnShow() / OnHide() / OnTargetChanged()
        void Say(text) / Refresh()

- 탭은 실행 중 한 번 만들어지고 자기 상태(선택, 검색어, 목록 위치)를 필드로 갖는다.
- 버튼 동작 뒤에 탭의 내용 영역을 지우고 다시 그리는 방식은 그대로다.
- 하위 화면(공법의 기술 추가·옵션 교체, 운명의 운명 고르기·역천개명·역천개명 고르기)은 `Push`로 쌓는다. 하위 화면 위쪽에는 같은 모양의 제목과 `돌아가기` 버튼이 나온다. 묶음 C·D의 "목록 → 세부 → 개별 가져오기"도 이 방식으로 얹는다.
- 탭을 떠나거나 편집 대상이 바뀌면 하위 화면을 모두 닫는다.

### 5.5 공통 부품

**ListView** — 스크롤 목록

    list.Build(parent, x, y, w, h, items, drawRow)   // drawRow(줄, 항목, 번호)가 한 줄을 그린다
    list.SetItems(items)                             // 걸러진 결과로 바꾸고 맨 위로
    list.Refresh()                                   // 보이는 줄을 다시 그린다

- 줄 높이는 목록마다 고정이다(한 줄짜리 32, 이름과 설명 두 줄짜리 50).
- 스크롤 영역의 높이는 `항목 수 × 줄 높이`이고, 화면에 걸친 줄만 만든다. 스크롤해서 첫 줄 번호가 바뀌면 그때 줄을 다시 만든다.
- 목록 위치는 부품이 기억한다. 탭이 내용을 다시 그려도 같은 위치로 돌아온다.
- 아래에 이동 줄: `처음` `이전` `다음` `끝`과 "전체 N개 중 a~b번째". `이전`·`다음`은 화면에 보이는 줄 수만큼 넘긴다. 전체가 한 화면에 들어오면 버튼을 숨기고 개수만 보인다.
- 항목이 없으면 "조건에 맞는 것이 없습니다" 같은 문구를 목록 자리에 보인다(문구는 쓰는 쪽이 준다).
- 홀수 줄에 옅은 줄무늬를 넣는다(지금 아이템 표와 같음).

**SearchBox** — 즉시 검색

- 입력 칸과 그 오른쪽 끝의 지움 버튼(`×`. 게임 글꼴에 이 글자가 없으면 `X`). `검색` 버튼은 없다.
- 글이 바뀔 때마다 앞뒤 공백을 뗀 검색어를 콜백으로 넘긴다. 쓰는 쪽은 걸러서 `list.SetItems`를 부른다. 탭 전체를 다시 그리지 않으므로 입력 칸의 포커스가 유지된다.
- Enter는 따로 하는 일이 없다(이미 걸러져 있다).

**DetailPane** — 상세 칸

- 목록 아래의 상자. 줄을 누르면 그 항목의 전체 이름과 설명을 줄바꿈해 보인다. 고른 것이 없으면 안내 문구를 흐리게 보인다.
- 줄에서 잘라 보이는 글(`…`)이 있는 모든 목록에 붙인다.

**Confirm** — 두 번 눌러 확인

- 확인이 필요한 버튼은 첫 누름에 이름이 "정말 ○○"로 바뀌고 결과 영역에 이유가 나온다. 한 번 더 누르면 실행한다.
- 확인 대기는 창 전체에 하나만 있다. 다른 동작을 하거나, 탭을 바꾸거나, 하위 화면을 오가거나, 검색어를 바꾸면 풀린다.
- 어떤 동작이 확인을 요구하는지는 지금과 같다(선천운명·게임이 붙인 운명의 삭제, 강제 추가, 망각, 잊기, 달력 직접 지정).

**AmountBar** — 수량 줄

- 1·10·100·1000 버튼, 직접 입력 칸, `적용` 버튼. 직접 입력 칸에서 Enter를 눌러도 적용된다. 범위 1~999999.
- 값은 용도별 열쇠로 따로 기억한다.

| 열쇠 | 쓰는 곳 | 기본값 |
|---|---|---|
| `attr` | 능력치의 증감 | 10 |
| `martialExp` | 공법의 숙련 경험치 | 10 |
| `move` | 순간 이동의 칸 수 | 10 |
| `intim` | 호감도의 증감 | 10 |
| `money` | 영석 추가량 | 10 |
| `item` | 아이템 지급 수량 | 1 |

**NumberField** — 숫자 칸

- 숫자만 받는 입력 칸. Enter를 누르면 값을 넘겨 적용한다. 숫자가 아니거나 비어 있으면 적용하지 않고 결과 영역에 알린다.
- Enter 없이 다른 곳을 누르면 적용하지 않는다.

### 5.6 탭별 변경

기존 검증 스크립트가 이름으로 확인하는 버튼과 입력 칸의 이름은 유지한다: `Day1`·`Day5`·`Day10`, `SkipMonth`, `Freeze`, `DateApply`, `DateYear`·`DateMonth`·`DateDay`, `BagMinus`·`BagPlus`, `God`, `Multiplier`. 그 밖의 버튼도 지금 이름을 그대로 쓰되, 목록 안의 버튼은 줄 번호 대신 항목의 번호(아이템 번호, 운명 번호 등)를 붙여 스크롤해도 이름이 바뀌지 않게 한다.

### 5.7 가방 칸 한 번에 지정

    가방 71/154 (편집기 추가 +90)   추가 칸 [  90 ] [적용]   [-10] [+10]

- 숫자 칸에 원하는 추가 칸 수를 쓰고 Enter 또는 `적용`. 10칸 단위로 내림하고 0~`BagService.MaxExtra`(500)로 맞춘 뒤, 지금 값과의 차이를 `BagService.Change(차이)`에 넘긴다. 차이가 0이면 그렇게 알린다.
- 서비스는 바꾸지 않는다. 이력에는 `Change` 한 번이 한 줄로 남는다.

### 5.8 변경 이력 전체 보기

    ChangeLog.ReadHistory(maxLines)   // changes.log의 마지막 maxLines줄. 읽지 못하면 빈 목록과 이유

- 안전 탭의 이력은 `changes.log`의 줄을 최신 순으로 보인다. 이번 실행의 기록도 이 파일에 들어 있으므로 따로 합치지 않는다. 읽는 양은 마지막 2,000줄까지.
- 파일을 읽지 못하면 지금처럼 이번 실행의 기록(메모리)을 보이고 이유를 적는다.
- "(재조회 불일치)"가 붙은 줄은 경고색.
- SearchBox로 대상 이름이나 항목을 거른다. 줄을 누르면 DetailPane에 전체가 나온다.
- 탭을 열 때 읽는다. 이력을 지우는 기능은 넣지 않는다.

### 5.9 개발 명령과 검증 도구

`Dev/DevCommandsUi.cs`(배포 빌드에서 제외):

| 명령 | 하는 일 |
|---|---|
| `uipos <이름>` | 편집기 안에서 그 이름의 요소를 찾아 가운데의 게임 좌표를 돌려준다. 여러 개면 첫 번째 |

기존 `EditorWindow.DevSetInput`, `DevMessage`, `DevDateState`는 같은 이름으로 남기고(날짜 상태는 `WorldTab`에서 읽어 넘긴다) `datebag-check.ps1`이 계속 쓰게 한다.

`tools/research/ui-check.ps1`(새 파일)이 `uipos`로 자리를 얻어 `rc.ps1 click`으로 누르고, 조회 결과의 경로가 그 이름으로 끝나는지 확인한다(가려져 있거나 자리가 틀리면 실패). `datebag-check.ps1`의 고정 좌표도 같은 방식으로 바꾼다.

| 21 | 전투에 들어가 편집기를 연다 | 편집기가 보이고 눌린다(카메라 방식이 안 되면 덧그리기로 열린다) |

| 23 | `MelonLoader\Latest.log` | 모드의 경고와 "trampoline" 예외 줄이 없다 |

사용자에게 직접 확인을 부탁할 것(도구로 시험할 수 없음): 실제 마우스로 제목 줄 끌기, 한글 입력기로 검색 칸에 입력.

## 7. 작업 순서

단계마다 편집기가 동작하는 상태를 유지하고, 단계가 끝날 때 게임에서 확인한다.

1. 검증 도구: `Dev/DevCommandsUi.cs`의 명령, `ui-check.ps1`의 뼈대, `datebag-check.ps1`을 이름 기반으로 바꿔 지금 화면에서 PASS를 확인한다.
2. 창의 틀: 캔버스 방식과 정렬, 제목 줄(끌기·접기·대상), 결과 영역, 켜 둔 기능 표시. 탭 내용은 기존 코드를 `EditorTab` 아홉 개로 옮기기만 한다(동작은 그대로).
3. 공통 부품 여섯 개.
4. 탭을 하나씩 새 부품으로 바꾼다: 자원 → 능력치 → NPC → 공법 → 운명 → 기예 → 세계 → 경지.
5. 추가 기능: 가방 칸 한 번에 지정, 안전 탭의 변경 이력 전체 보기.
6. 전체 검증(6절), 배포 구성 확인.
7. 문서와 병합, 설치.

## 9. 위험

| 위험 | 대응 |
|---|---|
| 전투·주 화면 등에서 UI 카메라가 없거나 다르게 동작 | 쓸 수 없으면 덧그리기 방식으로 그린다. 전투는 6절 21번에서 확인하고, 주 화면은 구현 중 확인해 05 문서에 적는다 |
| 지도 화면 안의 자식 캔버스가 편집기(정렬 10) 위로 올라옴 | 발견하면 그 값을 넘는 정렬을 쓰도록 `Raise()`의 덧셈을 조정한다(20 미만이어야 한다) |
| 한글 입력기로 치는 동안 즉시 검색이 어색함 | 검색 방식이 SearchBox 한 곳에 있으므로, 사용자 확인에서 문제가 나오면 Enter를 눌렀을 때 거르도록 바꾼다 |
| 스크롤 막대를 끄는 동안 줄을 계속 다시 만들어 끊김 | 첫 줄 번호가 바뀔 때만 다시 만든다. 그래도 끊기면 줄을 재사용하는 방식으로 바꾼다 |
| 탭을 옮기다 기능이 빠지거나 달라짐 | 탭을 하나씩 옮기고, 옮길 때마다 6절의 그 탭 항목을 게임에서 확인한다. 5.6절의 "그대로인 것"을 점검표로 쓴다 |
| 화면 배치가 바뀌어 기존 검증 스크립트가 깨짐 | 작업 순서 1번에서 이름 기반으로 먼저 바꾸고 지금 화면에서 PASS를 확인한 뒤 화면을 고친다 |
| `Tick`(매 프레임)의 예외 | 예외를 밖으로 던지지 않고 한 번만 로그에 남긴다(`BagService.Tick`과 같은 규칙) |
| `config.txt`에 위치를 쓰다 실패 | 위치를 기억하지 못할 뿐 동작에는 영향이 없다. 로그에 한 번 남긴다 |
